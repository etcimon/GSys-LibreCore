# `agents/` — transitional shadows only

This directory is **staging, not a destination**. The agentic surface of a submodule belongs **inside the
submodule** — `<id>/AGENTS.md`, its condensed `AGENTS-*` companions, its `AGENTS-todo.md`, and its
`architecture/` note set — because that is what makes the tree developable on its own terms and
independent of this scaffold ([`../AGENTS.md`](../AGENTS.md) §0.1,
[`../AGENTS-bootstrap.md`](../AGENTS-bootstrap.md) §4).

A file `agents/<id>.md` therefore exists only in the cases where the in-tree surface cannot yet be
written: the pin is checked out read-only, the branch that will carry the surface has not been decided,
the promotion is unfinished and the working notes need somewhere to live, or the submodule has not been
fetched at all and only a `planned` stub from B0 exists. In each of those cases the shadow holds the same
material in the same form as the in-tree guider — the template in
[`../AGENTS-bootstrap.md`](../AGENTS-bootstrap.md) §5.1 — so that moving it in-tree is a relocation
rather than a rewrite.

At emancipation (B7) the shadow is deleted, or reduced to a single line pointing at the submodule's own
guider for the benefit of anyone who arrives from the scaffold rather than from the checkout. Nothing of
value may remain here afterwards: if deleting this directory would lose information, that information has
not yet been moved, which is itself the open item.

The steady state of this directory is therefore **empty or nearly so**. A `agents/` directory that has
grown a guide per submodule and kept them is a scaffold that has quietly become a governance layer, which
is the outcome the ladder exists to prevent.
