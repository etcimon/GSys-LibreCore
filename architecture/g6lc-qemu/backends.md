# `g6lc_qemu` — backends B0–B3, machine profiles, MTTCG

Parent: [`README.md`](README.md) · Input contract: [`generator.md`](generator.md) (`TargetModel`).
Package implementation: `g6lc_qemu/crates/{g6q-emit-args,g6q-emit-qemu,g6q-vm}`.

**One generator, one IR, four emitters.** No backend reads a repo file directly; all of them read the
`TargetModel`. That is what keeps them consistent with each other and with the RTL.

---

## 1. The four backends

| # | Backend | Output | License of output | Needs | Primary use |
|---|---|---|---|---|---|
| **B0** | Stock-QEMU driver | argv + generated `.dtb` + `-cpu rv64,<props>` | none (no code emitted) | a stock `qemu-system-riscv64` | zero-fork bring-up, day-one Linux boot on an *approximation* |
| **B1** | Generated QEMU machine + CPU | C into a QEMU checkout | **GPL-2.0**, separate work | `--qemu-src` | faithful full-system `g6lc-soc` / `g6lc-virt` |
| **B2** | Generated TCG plugins | C against the QEMU plugin ABI | **GPL-2.0**, separate work | a plugin-enabled QEMU | D1 + D2 diagnosis inside QEMU |
| **B3** | Native Rust VM | Rust in-tree | **MIT** (tier T) | nothing | tandem oracle, deterministic replay, CI without a QEMU build |

`--backend args|qemu|rust` selects the family; `--emit` selects what `gen` writes.

### 1.1 B0 — stock-QEMU driver (Q2)

Emits **no code**. It composes:

- a `.dtb` generated from the `TargetModel` (or the repo `.dts`, overlaid),
- a `-cpu rv64,<prop>=<val>,…` string built from the resolved extension set,
- `-machine virt` plus `-bios`/`-kernel`/`-initrd`/`-append`/`-drive`/`-netdev` per the CLI,
- a **capability delta report**: every model fact stock QEMU cannot express.

That delta is the point. Stock `virt` has a different memory map, a different PLIC geometry, no
`g6lc,ai-matrix` device, and no notion of `NrScoreboardEntries`. B0 tells you exactly what you are
*not* testing, and gets a kernel booting on day one so that OpenSBI, DTS and rootfs plumbing are
debugged before any C exists.

### 1.2 B1 — generated QEMU machine + CPU (Q4)

Emitted files (names indicative; the emitter owns them):

| File | Contents |
|---|---|
| `hw/riscv/g6lc_soc.c` | `g6lc-soc` machine: memory map from `soc.peripherals`, CLINT, PLIC (`sources`/`targets`), ns16550a UART, ROM, DRAM, optional SPI/Ethernet/Timer/HPS |
| `hw/riscv/g6lc_virt.c` | `g6lc-virt`: `g6lc-soc` + virtio-mmio transports + larger RAM |
| `hw/riscv/g6lc_ai_island.c` | the `Xg6lcai` island device (see [`ai-island.md`](ai-island.md)) |
| `target/riscv/g6lc_cpu.c` | CPU variants per target id, extension gating, `mvendorid`/`marchid`/`mimpid`, custom CSRs |
| `target/riscv/insn_trans/trans_xg6lcai.c.inc` | custom-2 T0 decode/translate |
| `hw/riscv/g6lc_soc_selfcheck.c` | generated assertions that the built machine's map equals `ariane_soc_pkg.sv` |
| `g6lc_generated.mak` / `meson.build` fragment | build wiring |

Every file opens with:

```c
/* DO NOT EDIT — generated by g6lc_qemu <version> from <target-model.json sha256>
 * SPDX-License-Identifier: GPL-2.0-or-later
 * This file is part of QEMU (a separate work). The generator that produced it is
 * MIT-licensed and does not link against QEMU. See architecture/g6lc-qemu/README.md §3.
 */
```

The **self-check** file is not decoration: it is how "faithful" stops being a claim. It asserts base
and length for every peripheral, `NumTargets`/`NumSources`, the DRAM window (1 GiB, or 512 MiB under
`NEXYS_VIDEO`), and the island window/IRQ, against constants carried in the model from
`ariane_soc_pkg.sv`. A machine that drifts fails at construction, not at hour six of a boot.

### 1.3 B2 — generated TCG plugins (Q5, Q7)

Follows the precedent already vendored in this tree:
`core/cache_subsystem/hpdcache/rtl/tb/qemu_plugin/` is an existing QEMU 10 plugin emitting HPDCACHE
memory traces. Plugins are the sanctioned diagnosis seam because they need no QEMU fork and have a
stable ABI.

| Plugin | Tier | Emits |
|---|---|---|
| `g6lc_rvfi.c` | D1 | `st_rvfi`-shaped commit records |
| `g6lc_uarch.c` | D2 | BP / TLB / cache models sized from the `TargetModel` |
| `g6lc_pmu.c` | D2 | PMU groups 0–4 shadow counters |

Detail: [`diagnosis.md`](diagnosis.md).

### 1.4 B3 — native Rust VM (Q3 →)

In-tree, MIT, no GPL anywhere on the path. Staged:

| Tier | Form | When |
|---|---|---|
| **T0** | decode-cached threaded interpreter | Q3 — correctness first; this is the tandem oracle and the trap-precise fallback |
| **T1** | basic-block JIT, chaining | post-Q7, only if profiling justifies it |
| **T2** | region/superblock JIT, register promotion | deferred; explicitly not required by any gate |

B3 owns the machinery that is awkward to bolt onto QEMU:

- **Deterministic time** — `mtime` advances on a fixed instructions-per-tick ratio, never wall clock.
- **Record / replay** of MMIO and interrupt delivery keyed on `(hart, instret)`.
- **Checkpoint export** in a shape the Verilator testharness can resume from
  ([`diagnosis.md`](diagnosis.md) §4).
- **Lockstep tandem** against Spike and against an RTL trace, first-divergence reporting.

Honest sizing: a threaded interpreter lands around Spike's order of magnitude (tens of MIPS). That is
ample for OpenSBI, directed suites and tandem, and *not* ample for an Ubuntu desktop session — which
is why B1 exists and why "almost-native" is a QEMU/MTTCG claim, not a B3 claim.

## 2. Machine profiles

Restating [`README.md`](README.md) §5 because it is the rule most likely to be violated in practice.

| | `g6lc-soc` (default) | `g6lc-virt` |
|---|---|---|
| Memory map | byte-faithful to `corev_apu/tb/ariane_soc_pkg.sv` | `g6lc-soc` + virtio window |
| DRAM | `0x8000_0000`, `DRAMLength` (1 GiB; 512 MiB under `NEXYS_VIDEO`) | configurable, may exceed the real part |
| Block / net | **none** (SPI + Ethernet windows exist but are not a Linux storage stack) | virtio-mmio blk / net / rng / 9p / console |
| PLIC | `NumSources=30`, `NumTargets=16` | same + virtio IRQ lines |
| AI island | GPIO window `0x4000_0000`, PLIC source 8, when `AiCfg.MatrixEn` | same |
| Valid for | **all** diagnosis, tandem, checkpoints, SoC-map / topology questions | OS bring-up only |

Enforcement:

1. `profile` is a field of the `TargetModel` and is stamped into every emitted artifact, trace header,
   PMU dump and JSON result.
2. `g6q diag` and `g6q tandem` **refuse** `g6lc-virt` unless `--allow-virt-diag` is passed, and when
   it is, every output line is prefixed `virt:` and the JSON carries `"profile_tainted": true`.
3. The B1 self-check runs only under `g6lc-soc`; under `g6lc-virt` it reports the deltas instead of
   asserting.

Why this is worth the ceremony: the faithful SoC **cannot** boot an Ubuntu rootfs — no disk, no NIC.
The temptation to "just add virtio to the real machine" would destroy the only property that makes
this tool trustworthy.

## 3. Accel: TCG + MTTCG (no host hypervisor)

**Decision: TCG, tuned; no KVM/WHPX backend.** ([`README.md`](README.md) §7 records the reopen
condition.)

The reasoning, stated once so it is not rediscovered: the guest is RISC-V and the host is x86-64, so
no hardware extension can execute guest instructions. The only thing a hypervisor buys a cross-ISA
emulator is *realising the guest address space in host page tables* so translated loads/stores skip
the software TLB (the Captive technique). That is a genuine ~2–4× — and it is a large, Linux-only,
in-VM-kernel subsystem that is extremely hard to debug and would sit on the critical path of every
diagnosis result. Not a Q0–Q9 investment.

### 3.1 What is invested instead

| Lever | Sizing input | Note |
|---|---|---|
| **MTTCG** — one vCPU thread per **logical hart** | `S = NrCores × NrHarts` | `--smp auto`. PLIC `NumTargets=16` ⇒ **`S ≤ 8`**; `CVA6_MAX_SMT_HARTS = 2` today. `NrIssuePorts` is **not** a hart and never appears in DTS (`../multi-threading/linux-boot-scale.md` §0). |
| Translation-block chaining / TB cache size | code footprint of the workload | `--tcg-tuning tuned` derives from the model rather than guessing |
| softmmu TLB sizing | guest working set | ditto |
| Atomics | `RVA`, `RVZacas` | RVWMO is *weaker* than x86-TSO, so ordering is free on x86 hosts; `amocas.q` maps to a 128-bit CAS (`../zacas-amocas-q.md`) |
| Fences | — | `fence rw,rw` is a no-op on TSO; `fence.i` and `sfence.vma` must invalidate translations, which is a correctness item, not a performance one |

### 3.2 SMT is not free

With `NrHarts = 2`, two vCPU threads share per-core state that the RTL banks per hart: AI CSRs
(`aicfg`/`aistatus`, and accumulators banked with `AiAccBanks ≥ NrHarts`), the SMT fetch policy, and
the shared TLB when `UseSharedTlb`. B1/B3 model the **banking**, not the arbitration — the emulator
reproduces *architectural* per-hart state correctly and leaves contention effects to D2 and to
Verilator. Saying that plainly avoids a class of bogus SMT performance conclusions.

### 3.3 Expected throughput (orders of magnitude, not measurements)

| Path | Rough | Fit |
|---|---|---|
| Verilator RTL | 10–100 kIPS | evidence |
| Spike | 20–100 MIPS | tandem reference |
| B3 T0 interpreter | 10–50 MIPS | tandem, replay, CI |
| B1 QEMU TCG | 200–500 MIPS | Linux boot in seconds, usable shell |
| B1 + D2 instrumentation | 5–30 MIPS | diagnosis |
| native x86-64 | 10+ GIPS | the ceiling |

"Almost-native" therefore means **an interactive guest that feels responsive**, not parity with the
host. Promising parity would be false; the honest claim is ~10⁴× faster than the Verilator path,
which is what changes the workflow.

## 4. Emitter contract

1. **Text out only.** No crate links, includes, or `bindgen`s QEMU. `E-GPLLINK`
   ([`README.md`](README.md) §3), enforced by `tools/check_independence.py`.
2. **Deterministic output.** Same model ⇒ byte-identical C. Canonical ordering everywhere; no
   timestamps in generated files (the model SHA is the identity).
3. **Banner + SPDX** on every emitted file (§1.2).
4. **Never tracked.** Emission targets `g6lc_qemu/out/` and `g6lc_qemu/qemu/`, both gitignored. A
   hand-edit is silently lost on the next `gen` — fix the emitter.
5. **Idempotent and diffable.** `gen --check` re-emits to a temp dir and diffs, so CI can assert "the
   checked-in model still produces the tree we think it does".
6. **One target per emission.** Multi-target builds are N invocations into N output dirs; a single
   QEMU binary carrying every LibreCore variant is a later convenience, not a Q-gate.
