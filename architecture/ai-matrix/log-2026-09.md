### Stage-2 characterization counters and first measured breakdown (2026-09-28)

`g6lc_ai_gemm_seq` now exports per-job phase cycles (LA/LB/MAC/STC) and stalled handshakes
(AR held, R offered but not taken, W held); the island holds them at job completion and
publishes them read-only at `PMU_OFF_PHASE_*`/`PMU_OFF_STALL_*` (0x0f50..0x0f68). The backend

new registers) PASS. `ai-measure-dpf0-20260928-r1` (8 lanes, 2 sim channels, k=16 unless noted,
free-running cycle counter, all goldens re-checked per run):

| shape (INT8) | cycles | LA | LB | MAC | MAC/cycle (of 8) |
|---|---:|---:|---:|---:|---:|
| 1x16x16 | 170 | 7 | 112 | 48 | 1.5 |
| 8x8x16 | 255 | 56 | 56 | 140 | 4.0 |
| 16x16x16 (ar=1) | 755 | 112 | 112 | 528 | 5.4 |
| 16x16x16 (ar=2) | 649 | 59 | 59 | 528 | 6.3 |
| 8x8x64 (ar=2) | 677 | 75 | 75 | ~520 | 6.1 |

Measured mechanisms, at this geometry: (1) **phases do not overlap** -- load A, load B and MAC
are strictly sequential, so operand loading is 44% of an 8x8x16 job and ~15-30% of larger
ones; (2) the MAC phase retires one output per `ceil(k_bytes/lanes)` cycles (16x16x16: 528
cycles for 256 outputs x2 steps, 97% of the phase ideal), so the engine is output-serial, not
lane-limited; (3) the AR depth cap only shortens the load phases (112->59 cycles per operand
at ar=2) and never the MAC phase; (4) no R backpressure or AR stalls occur against the class-0
model; W stalls equal the number of C beats (one bubble per 8-byte store pair); (5) FP16/BF16
double and FP32 quadruple the MAC phase because rows are 2x/4x the bytes through the same
lanes, exactly as the byte-row rule predicts; INT4 halves loads and MAC steps. Store cycles
are hidden inside MAC (trail stores), STC=0 for all shapes. These are reduced-geometry model
measurements (8 lanes, simulation memory with register slices), not live-512 or silicon
numbers; they establish the Stage-3 priorities -- load/compute overlap (double-buffered A/B)
and more than one retiring output per cycle -- ahead of any lane-count growth.

finer scales cost no extra device work (1350 blocks for the 256-token pass). The tied
embedding `lm_head` (50257 x 768) is the quantization-sensitive layer; the transformer blocks
are not. FP32/BF16 offload of this model is impossible under the current contract because
K=768/3072 exceeds AccTile K=512 and ordered-FP K-splitting is refused -- resident K
accumulation (Stage 3) is therefore also a *model-support* requirement, not only a
performance one. Offloaded pass took 12-19 s in the pure-Python/NumPy reference versus 0.18 s
in torch; this is host reference speed, not an island projection.

### Accumulate mode (accmode 01) as an extension, and FP32 model offload (2026-09-28)

Resident K accumulation was needed for model support (K=768/3072 > AccTile 512 for every
distilgpt2 float layer). Rather than a new field, the reserved `flags.accmode == 01` is
enabled behind a new RO grant word `CAP_OFF_ACCMODE` (0x94, bit 0): the reduction of every
C[i][j] is *seeded* from the stored i32/f32 word, so a host K-split equals one ordered
reduction bit for bit. Extension ABI 2.2.0 (`requires:desc-v2-k-major+accmode-v1`); no
descriptor/completion change. Implemented in the Python and Rust references
(`gemm_native(c_init=)`, `gemm_native_acc`), `Caps.accumulate`, `check_desc_engine_acc`, the
SoftIsland/Sim engines (refuse without grant, seed with it; poisoned-C negative kept), the
C/Python/Rust constants (51-macro lockstep) and `torch_backend` (float K blocks chain through
the seed; refused with a named reason on ungranted devices). The live sequencer publishes
`AiIslandAccmodeGrant = 0` and keeps refusing with ST_BAD_FMT; `g6lc_qemu` ingests the word
and refuses to invent it. No-DMA spine `ai-spine-accmode-20260928-r1` PASS.

`fixtures/qual/distilgpt2-fp32-accumulate.json`: all 25 linears (incl. lm_head) offloaded in
FP32 through 426 chained blocks -- ppl 46.5066 -> 46.5064 (-4e-6 relative, reduction-order
noise vs BLAS), **top-1 agreement 1.000**, max |dlogit| 3e-4, zero fallbacks: PASS. Software
reference at live geometry, 54 s per 256-token pass (host reference speed, not an island
projection). RTL follow-up: an `ST_LC` C-seed load in `g6lc_ai_gemm_seq` (m x n x 4 bytes into
the C bank, MAC first step `acc = fp32_add(c_seed, sum)`), then flip the grant with directed
tests that compare a chained K-split against one long job bit for bit. The RTL float lane
tree ordering versus the sequential software order remains the Stage-4 profile question.

### Execution-path analysis, quick local bench, and the first area cut (2026-09-29)

**Quick bench on the local host.** The remote review runner (`run_ai_spine_review.py`) is
portable: with the pinned Verilator 5.008 under WSL (same `verilated_funcs.h` hash as the
remote, so the CONSTHI repair applies) `verif/regress/ai-ops-bench.sh` runs the backend

verdict per record). Wired into `build-platform` as `ai-ops-bench` (local) and
`ai-ops-bench-soc` (the SoC model: `verif/tests/custom/ai/ai_bench_gemm.S` assembled per

failure (`qualification.test.ts` isolated L2 proxy) reproduces with these edits stashed.

**What the numbers say (8-lane bench, simulated stripe; sequencer behaviour, not live
timing).** MAC phase: INT8/FP8 run at 0.97 of the byte-lane ideal `m*n*ceil(k/lanes)`,
FP16/BF16 at 0.985 of *half* that rate and FP32 at 0.99 of a quarter -- the PE issues
PeLanes **bytes** per step, so MACs/cycle scale 1 : 1/2 : 1/4 (INT4 2x) by construction, and
the live 512-lane island is 512 / 256 / 128 / 1024 MAC per cycle per format. Loads: at
K=16 a row is 2 beats, so every row pays the stripe latency -- 3.5 cycles/beat at AR depth
1, 1.84 at depth 2 (AR depth 2 is the live setting); loads are latency-bound at small K and
bandwidth-bound (1 beat/cycle) at live K=512 where a row is 64 beats. Stores overlap the
MAC (STC = 0) except odd N: n=1 columns take single-word writes and the MAC phase absorbs
their stalls (16x1x16: mac_eff 0.28, `stall_w` 48). So per operation the wall is the byte
stream (loads), the MAC is at rate, and the store path only matters for odd N.

**Ranked sequencer levers (cycles per op at fixed area):** (1) merge contiguous rows into
one AR burst when `lda == k` / `ldb == k` -- removes the per-row latency at small K (up to
2x on loads there, modest at live K); (2) even-up odd-N C rows (pair stores with a
masked last word) -- removes the n=1 penalty for GEMV outputs; (3) AR depth is already
the right knob at live K; (4) load/MAC overlap only helps latency-bound small tiles because
the single 64-bit port is saturated at live K -- residency (reuse flags) and batching M are
the bandwidth levers, as the VA-Turbo selection quantified on the byte side.

**Area cut from the coarse netlist.** The reduced-island synthesis carried 3 `$div` and 48
`$mul` coarse cells; the dividers were runtime divides by the element size
(`PeLanes / ai_fmt_bytes()`) and by the beat/lane minimum in `beats_for_rem`, and several
multiplies were `t * ai_fmt_bytes()`. Every element size is 1/2/4 bytes, so these are now
shifts (`ai_elem_shift`, `ElemsPerBeatShift`); the bench is **cycle-identical on all 156
records** before/after and functional/negative pass. The remaining multipliers are the
row-address products `i * stride` in the A/B cursors (and spans), replaceable by
incremental row pointers -- next area item, verifiable with the same 1-minute bench.
Yosys re-count of the cells waits for the remote (busy with the owner's boots); the
divider removal is by construction (no `/` on a runtime operand remains in the sequencer).
`ST_LC` cycles are billed to the LA phase word.

### SoC completion-identity anomaly: root cause found, test-suite defect (2026-09-29)

The waveform session ran once the remote was free (trace model `work-ver-ai-trace`,

### Flat panel mapping: K-split-to-residency (2026-09-29)

**Adjustment.** `g6lc_ai_gemm_seq` stores operand rows at a per-job pitch of
`2^pitch_sh_q` bank words (`pitch = next_pow2(ceil(k_bytes / PeLanes))`, computed in
`ST_CHK`, registered for the job) instead of the fixed `LimK` pitch. The K box becomes a
**byte capacity per panel**: `n * pitch <= OperandWordsB`, `m * pitch <= OperandWordsA`,
`k <= 65535` (`cap_ok_c`, also the reuse `geometry_ok`); `m <= LimM`, `n <= LimN` stay
(the C bank pitch is unchanged). Bank addresses are `(row << pitch_sh_q) + (t >> LaneShift)`
-- a shift, no runtime multiplier (`PeLanes` power of two asserted); the reuse key's `k`
widens to 16 bits. Cost: up to 2x row slack when `k_bytes` is not a power-of-two multiple
of `PeLanes` (e.g. k = 768 B rounds to a 1024 B pitch). Published as
`CAP_OFF_BANK_A_BYTES` (0x98) / `CAP_OFF_BANK_B_BYTES` (0x9C) = `OperandWords * PeLanes`
(`ai_operand_bank_bytes`); a part publishing 0 keeps the legacy `k <= AccTileK` box.
Effect: a 256 x 1024 INT8 weight panel (the same 256 KiB as 512 x 512) is **one job and one
resident key** -- no `accmode` K-split, so `FLAG_REUSE_B` hits on decode; and on the FP SKU
(`IslandFpEn`, 4-byte-sized banks) INT8 jobs may use the full 1 MiB per operand.

### Two-slot resident-B directory, decisions on the remaining sequencer levers (2026-09-29)

**Why a directory and not the other levers first (analysis of the measured execution
paths).** The SoC records put the decode job at 1.002-1.008 cycles per B beat with AR
depth 2 (`lb` 33,034 for 32,896 beats; FP32 131,842 for 131,584): the AR handshake
overhead that **row-merged AR bursts** would remove is under 1 % on every ML-shaped row
(>= 64 beats), and the skinny rows where merging helps (k of a few beats) are not what
LLM/diffusion layers issue. **Odd-N single-word stores** only occur for odd column counts
(the bench's `n = 1` transposed GEMV, mac_eff 0.28) -- hidden sizes are even. Both are
deferred with this basis. The lever that changes real decode is residency for a layer whose
N spans two panels: GPT-2's 768 columns are a 512 panel and a 256 panel issued
alternately every token, so a single resident key thrashes exactly like the K-split did.

**Adjustment.** `g6lc_ai_gemm_seq` `ReuseBSlots` (default 2; island_top parameter): the B
bank is split into `SlotsB` halves with one key each (`ptr, n, k, ldb, fmt, epoch`), the
incoming job's key is checked against every slot, the hit slot (else the round-robin
victim -- LRU for two) becomes the job's `cur` slot and its key is dropped at start and
re-established at `ST_DONE`. Placement is decided in `ST_CHK` from the flat-panel pitch:
`n << pitch <= SlotWordsB` puts the panel at `cur * SlotWordsB` (`b_base_q`, added to the
B bank row address), otherwise the panel is "big", takes the whole bank at base 0 and
invalidates every other slot; a small panel landing beside a big resident evicts it. A
hit without `FLAG_REUSE_B` is not taken (software consent). Invalidation/response error
clear all slots. A is unchanged (single key: decode `m = 1` A panels are one row).

**Evidence.** Local bench, both float pipes: `+review_slots` **PASS 16 checks** -- two
INT8 panels with different data alternate and both hit (`lb = 0`) with correct, distinct

is itself resident, and is evicted by the next small panel; invalidation drops all. The

## 2. Nameplate sketch and the 48× gap

Plan of record is [`scaling-100tops.md`](scaling-100tops.md) (I0–I4). Ordering
is bandwidth before MACs. The target is 100×10¹² dense INT8 ops/s (one MAC =
two ops; sparsity and INT4 stay out of the headline).

INT8 milli-ops = `2 × clusters × macs × (clock_khz/1000) / 1000`. INT4 is ×2.
FP8 (codes 3 and 4) matches INT8. FP16/BF16 (codes 5 and 6) are half. FP32
(code 7) is a quarter. Structured 2:4 (code 2) and unknown codes are 0.
`sketch_milli_tops_scaled` projects a rate and elaborates no lanes. VA levels
0–15 leave the dense peak unchanged. A level above 15 or a zero multiplier
returns 0.

| Code | Format | Live milli (1×512 @ 2 GHz) | Throughput sketch (8×4096 @ 1.5 GHz) |
|---|---|---:|---:|
| 0 | INT8 | 2048 (2.048 TOPS) | 98304 (98.3 TOPS) |
| 1 | INT4 | 4096 | 196608 |
| 2 | structured 2:4 | 0 | 0 |
| 3, 4 | FP8 E4M3 / E5M2 | 2048 | 98304 |
| 5, 6 | FP16 / BF16 | 1024 | 49152 |
| 7 | FP32 | 512 | 24576 |

Live MAC/s = 1 × 512 × 2×10⁹ = 1.024×10¹². The throughput sketch is
8 × 4096 × 1.5×10⁹ = 4.9152×10¹³ MAC/s. The ratio is exactly 48× in every
expressible format: `(8/1) × (4096/512) × (1.5/2) = 48`. A VA level does not
scale either column. 4096 is not a physical MAC array.

`AiIslandThroughputSku` is 8 clusters × 4096 MAC/cycle, accumulator K 4096,
1.5 GHz, DRAM class LPDDR5 nameplate 400 GB/s (`AI_DRAM_LPDDR5_GBPS`), format
mask `16'h00fb`, SRAM field 2 MiB. `tb_g6lc_ai_throughput` elaborates that
sketch. Class 2 with `Class2Model=0` still `$error`s and elaborates no PHY.
I0 and I3-lite are closed on the live machine. I1 is partial. I2, class-2
DRAM, and I4 are unstarted. I2 must leave I1/I3 latency-SKU results
bit-identical. The I2 numeric gate remains at least 60% of peak on a 4096³
GEMM, and I2 stays behind a carried port wider than 8 bytes/cycle.

The core-attached plane is a fixed 8×8×8 CVXIF tile. It is not the scaling
path. Option D and the Ara superscalar/RVV conflict are off this path.
`contracts.ai_host_transport` stays unpublished (GPEX RC and virt_ai_card EP
stay separate).

## 3. Formats, the float model, and the policy block

ISA numfmt codes: 0 INT8, 1 INT4, 2 structured 2:4, 3 FP8 E4M3, 4 FP8 E5M2,
5 FP16, 6 BF16, 7 FP32. Width, not the format id, selects the lane. Structured
2:4 is refused on every mask. `ST_OK` is 0. `ST_BAD_FMT` is 8. An ungranted
mode is not demoted to INT8.

`LIVE_DTYPE_MASK` is `0x0003`. `FAST_DTYPE_MASK` is `0x00fb` (every ISA format
except structured 2:4). Integers need the grant bit. Floats need the grant bit
and `fp_datapath`. The synthesizable strip passes `fp_datapath` false, so a
fast mask still refuses FP8/FP16/BF16/FP32. `software_reference_v2` sets mask
`0xfb` and `fp_datapath` true. QEMU refuses a float grant the same way: the
flag defaults false, and `model_granting` sets it so functional goldens still
run.

`g6lc_ai_cluster_tile` is the non-default strip engine (`AI_THROUGHPUT_LANES`
is 8 physical multipliers). The live package instantiates `gemm_seq` at
`AI_LIVE_MACS` INT8/INT4 lanes. `g6lc_ai_fp_dot` is a non-synthesizable `real`
reference and elaborates only when `FP_REAL_MODEL` is set. Inside that
generate the hierarchical name is `gen_fp_model.i_fp`. The 2×2×2 INT8 tile
`A=[[1,2],[3,4]]`, `B=[[5,6],[7,8]]` writes `C=[[19,22],[43,50]]` for both
8 lanes and 1 lane. The same 8-lane tile in FP32 writes binary32
`0x41980000`, `0x41B00000`, `0x422C0000`, `0x42480000`.

The policy block in `g6lc_ai_island_top.sv` records a PMU snapshot
(`0x0190`–`0x019C`) and does not drive `gemm_numfmt`. The GEMM instance uses
`gemm_numfmt_o` from the descriptor engine. `gemm_seq` does not call
`va_turbo_select` and does not read the level, recipe, or window registers.
The 64-byte descriptor has no approximate-execution field, so the descriptor
level stays 0.

## 4. VA-Turbo gate

VA-Turbo is exact operand reuse on `config_pkg::AiCfgVaTurboTest` only. It
adds no lanes and it is not the path to the dense-INT8 headline.
[`va-turbo.md`](va-turbo.md) is the completion-path contract. Steps 1–6 are
done on that test geometry and on the matching host paths. Step 7, copying
`VaTurboEn` onto `g6lc64`, stays locked. Ingest fails if the live bit and the
test bit swap.

`check_cfg` requires `VaTurboEn` to imply `PolicySubcodeEn` and `IslandFpEn`.
The chain is `VaTurboEn` → `PolicySubcodeEn` → `PolicyBenefitEn` →
`PolicyCodecEn` → matrix plane plus a T2 queue. `IslandFpEn` also requires
`MatrixEn`, `Queues > 0`, RVF, and RVD. The directed config is that chain with
an INT8 format mask, 8 MAC/cycle, and tile 1024×512×16
(`AccTile::VA_TURBO_TEST`, `VA_TURBO_TEST_MACS = 8`). Only
`tb_g6lc_ai_desc_reuse` sets `VaTurboEn`. Production `g6lc_ai_island_top`
binds presence to `AiCfg.VaTurboEn`. On the live package that bit is clear, so
a descriptor flag does not skip an operand. The epoch register is the
ownership storage. Hardware does not snoop A or B writers and does not enforce
the writer lease. The caller advances the epoch after touching A or B.

Flag bit 15 (`FLAG_REUSE_B`, `1<<15`) and bit 23 (`FLAG_REUSE_A`, `1<<23`)
request a residency skip. They do not change the MAC issue count. The live
island ignores both while `VaTurboEn` is 0. One resident slot holds the
previous tile. B skips when the previous tile matches `j0`, `tn`, `t0`, and
`tk`. A skips when it matches `i0`, `tm`, `t0`, and `tk`. A K split changes
`t0`, so neither flag is set. The two flags are never both the reason for one
adjacent step. Keys are `DimW` bits from the larger of M, N, and K, so they
hold 1024. B's key is pointer, N, K, `ldb`, format, and epoch. A's key is
pointer, M, K, `lda`, format, and epoch. Format is flags numfmt at
`FLAG_NUMFMT_SHIFT=20`. A hit needs the request, a valid installed key,
matching fields, A/B disjoint from C, and no invalidate or AXI response error.
A hit multiplies the bytes captured when the key was installed. A new epoch
misses. A C range that overlaps the operand drops that key. A failed dot drops
both keys. A completion-beat error keeps the resident key, because keys commit
when the dot finishes.

Section 11 stays off this register track: lane groups, compact FP reductions,
converters, proof producers, approximate consumers, and multi-cluster.
`section11_selected()` is false. Lane groups do not raise MAC/s. Spare lanes
are retire-bound (at most one C element per cycle). INT8 k=16 at `PE_LANES` 16
versus 32 is byte-identical. Grouping would need more write ports. The 91.5×
figure in `va-turbo.md` for a 1×256×256 resident-B shape is a model ceiling.

### Registers inside the 4 KiB window

The block sits at `0x0F00`–`0x0F18`, above the live 2-queue decode that ends
at `0x01C0`. Offsets `0x2200`–`0x2218` are outside the 4 KiB device, so a
guest store at `base+0x2200` misses the island. Doorbell ticket literals and
C constants that contain 2200 are not register addresses. QEMU resolves the
ingested localparam short names `reuse_epoch`, `va_turbo_level`,
`va_turbo_recipe`, and `va_turbo_window`.

| Offset | Register | What a write stores |
|---|---|---|
| `0x0F00` | epoch | Full 32 bits. Forwarded to `gemm_seq` only when `VaTurboEn` is set. Live pins stay 0 |
| `0x0F04` | level request | Bits `[3:0]`. Applied nibble `[11:8]` stays 0 |
| `0x0F08` | level PMU | Copied at `gemm_done`. Applied nibble stays 0 |
| `0x0F0C` | recipe request | Bits `[4:0]` = `{bank, subcode}`. Applied id `[12:8]` stays 0 |
| `0x0F10` | recipe PMU | Copied at `gemm_done`. Applied id stays 0 |
| `0x0F14` | evidence window | Cleared by any write of epoch, level, or recipe, including a same-value rewrite |
| `0x0F18` | window PMU | Copies the window bit at `gemm_done` |

A write of `32'h109` at `0x0F04` reads back 9. A write of `32'h110` at
`0x0F0C` reads back 16. The 2×2×1 all-ones product stays 1. The host level-9
schedule stores the request and the 8×8×8 product stays all 8s.
`run-desc-reuse` on the directed island printed `epoch=1 lvl=1 recipe=1
window=1`.

## 5. Directed exact-reuse schedule

Exact reuse runs only when the device's own capability record is the directed
8-MAC 1024×512×16 tile and an adjacent planned tile can skip an operand.
`exact_reuse_for_call` and Rust `directed_tiles_can_skip` are that predicate.
A host caps override is not a capability record. A publishing device that
reports a different tile wins, and the schedule stays off. Applied level stays
0 on every path. A level or a recipe does not change C.

`run_gemm_s8_auto` calls `execute_va_turbo_test_s8_at` only when
`directed_tiles_can_skip` is true. Otherwise it stays on `run_gemm_s8_stream`.
The last ticket is `ticket + ntiles - 1` with status `ST_OK`. Python
`Device.gemm_s8` with `auto_tile` uses the same rule.
`_directed_schedule_caps` walks the qemu-uio session, the virtual card, and
the native device. A `reports_directed_tile` result of false returns none, so
a caps override cannot enable the schedule. With no publisher, the caller's
caps are the model, and they enable the schedule only when they themselves
are the directed tile. `run_high_level_s8` calls `Device.gemm_s8` and then
overlays `high_level_fields`, restoring hit and read bits when reuse ran.
PyTorch, NumPy, and TensorFlow share that one decision. `auto_tile=False`
does not enter the named-panel schedule.

A K-split on the directed tile has no adjacent skip, so auto stays one
ordinary job. The dedicated `run_va_turbo_test_s8` plan can still split
8×8×16 into two k=8 panels whose products sum to 16. Auto does not take that
split. `va_panels=True` on a device that is not the directed tile tiles
without enabling reuse. The default stream stays on the 1024×512×512 box.

Tile DMA keys on the qemu-uio window are pointer plus shape. Equal-shaped
tiles share DMA addresses, so a K-split must leave both flags clear. A flag
on that split would false-hit. The guest driver cannot set `VaTurboEn`.
`reuse_enabled` on a session is the schedule decision.

| Path | When the schedule runs | When it stays off |
|---|---|---|
| Rust `run_gemm_s8_auto` | Directed tile and an adjacent tile can skip. 16×8×8 skips B across two tickets. 8×16×8 skips A | Directed K-split stays one ordinary job, reuse off, C all 16s. Any other capability record stays on the ordinary stream |
| Python `Device.gemm_s8` auto | Same predicate. Ticket 5 on 16×8×8 returns ticket 6, two tiles, B skipped, C all 8s. 8×16×8 at ticket 4 returns ticket 5 and skips A | 8×8×16 at ticket 9 stays ticket 9, one tile, reuse off, C all 16s. A 512-MAC device at ticket 3 stays one tile. A published capability record wins over a host caps override |

`software-reference-v2` sets the native module aside and uses the caller caps
(or dtype mask `0xfb` when the caller passes none). It publishes no
`reports_directed_tile`. When those caps are the directed tile, the high-level
path runs the host schedule. A pure-Python simulator, with the native module
absent, does the same when its caps are that tile.

Products on every aligned path, all-ones operands, applied level 0:

| Shape | Split | Reuse | C |
|---|---|---|---|
| 16×8×8 | M, two 8×8 panels | Second tile sets bit 15 and skips B. `hit_b` true, `hit_a` false, `read_b` false | all 8s |
| 8×8×16 | K | Both flags clear. Both operands read. Auto stays one ordinary job | all 16s |
| 8×16×8 | N, two 8×8 panels | Second tile sets bit 23 and skips A | all 8s |
| 8×8×8 | one tile, including requested level 9 | `reuse_enabled` false | all 8s |

On the directed window, a 1×1 primed with B=2 and then overwritten to 9 keeps
2, because the flag hits the captured byte. The same sequence on a window
that is not the directed tile returns 9.

`reuse_blocked` is absent only when exact reuse ran. It is `shape` when the
shape does not ask for a resident operand (16×8×8 is tall in the workload
table and still has `n > 1`, so it does not nominate A; 8×8×16 is bulk). It
is `live-caps` when the shape would skip and the caps are not the directed
tile (1×600×8 and 1×8×600 on the live device). It is `native-call` for one
native GEMM, checked before `live-caps`. It is `not-enabled` when the
predicate was true and the call still did not reuse. A one-row N-split
nominates resident B and the tile walk hits A: `shape_reuse_b` stays true and
`hit_a` records the skip. 1×256×256 is a K-split, so exact reuse stays off
even on the directed tile. `high_level_fields` reports `carried_bytes` 8 and
`port_promoted` false on the live 64-bit fabric. `fed` uses this device's
clusters × macs against the carried bytes and the 8-byte control beats. One
cluster of 512 on 64 bits is fed. Eight clusters of 4096 on `noc_width` 64
are not.

Descriptor reuse on the directed RTL island (`run-desc-reuse.sh`,
`AiCfgVaTurboTest`) covers the same three shapes (`sched=1`, `ksplit=1`,
`nsplit=1`) plus pointer, stride, format, epoch, odd-n tail stores, A-read
SLVERR, B-read SLVERR, C-store SLVERR, and the completion-beat SLVERR. Those
checks are on the 8-MAC copy. They are not a measurement of the live 512-MAC
array. `run-gemm-panel-reuse.sh` is the opt-in class-0 N=1 directed build
(`MaxM=1024`, `MaxN=512`, `MaxK=16`, `PeLanes=8`) and is not the live package.

## 6. Carried port, balance, and the DRAM claim

`carried_bytes_per_cycle` is `min(island_bits, fabric_bits) / 8`. Helpers live
in `g6lc_ai_island_cfg_pkg.sv`, `format_trace.rs`, and `python/ai_tensor/va_turbo.py`.
A 512-bit island DMA joined onto the live 64-bit fabric is still 8 bytes/cycle,
so `AI_LIVE_MACS` stays 512. `macs_may_rise` is true only when carried bytes
are greater than 8. A matched 512-bit fabric would carry 64 bytes/cycle.
Descriptor, C, and completion beats stay 8 bytes (`NARROW_BEAT_BYTES`) even
when the data DMA is wider.

A legal data width is a power of two from 64 through 4096. A legal control
beat is a power of two from 8 through 512. Any other width (96, or 12) carries
0 and is not promoted. `PortSetting.live` is island 512 on fabric 64: 8
bytes/cycle, not promoted, effective MAC count 512. A 256-bit fabric carries
32 bytes/cycle and may use the configured MAC count. A VA level does not scale
the live 8-byte port. The default xbar stays 64-bit.
`G6LC_AI_DRAM_ISLAND_PORT` is 512 bits internally and narrowed at the join. It
is not a faster port and stays off by default.

`LIVE_MACS_PER_BYTE` is 64. `keeps_pace` is carried data bytes > 0 and total
MACs ≤ carried × 64. `control_keeps_pace` uses the control beat the same way.
`fed` is both. The live chip is fed: 512 MAC/cycle on 8-byte data and 8-byte
control, demand 16 GB/s at 2 GHz, class 0 covers it. Widening the data fabric
does not widen the control beats. The 8×4096 sketch needs 512 bytes/cycle on
the data port (a 4096-bit fabric) and 512 bytes/cycle on the control path
before `fed` is true. Lane groups, float reductions, converters, and proof
producers do not change the rate.

`configured_rate` scales cluster and MAC counts only on a promoted port. The
live 64-bit fabric stays 1×512 and 2048 INT8 milli-ops. A 256-bit fabric with
4 clusters × 2048 MAC/cycle at 2 GHz sketches 32768 INT8 milli-ops, 65536
INT4, and 8192 FP32 (MAC/s 16.384×10¹²). That array is 256 MAC/byte and needs
128 bytes/cycle to keep pace. With control left at 8 bytes, `fed` is false.

Class-0 nameplate GB/s truncates `clock_khz/1_000_000`, so 1.5 GHz counts as
1 GHz. Live 8-byte data and control at 2 GHz publish 16 GB/s each. The fed
8×4096 setting with 512-byte data and control paths publishes 512 GB/s each,
not 768. `demand_gbps` is the bytes required to hold 64 MAC/byte, times that
truncated gigahertz.

DRAM caps: class 0 is the carried data nameplate, class 1 is channels × 19
GB/s (DDR4-2400×64), class 2 is flat 400 GB/s and ignores width and clock, and
any other class is 0. RTL enums are `AI_DRAM_SIM_AXI=0`, `AI_DRAM_DDR4=1`,
`AI_DRAM_LPDDR5=2`. `dram_covers` requires `fed`, `demand_gbps > 0`, and a cap
at least as large as the demand. `dram_claim_matches` requires the claimed
rate to equal that cap and the class to be at most 2, with one exception: a
class-2 claim of 400 is rejected when 400 is also the class-0 nameplate. A
matching claim does not change the live DRAM class. The live chip stays class
0, one channel, `VaTurboEn` 0. One DDR4 channel covers 16 GB/s. The fed
8×4096 sketch demands 512 GB/s: class 0 covers it, and class 2's 400 does not.
`ddr4_channels_to_cover(512)` is 27. Twenty-six channels are 494 GB/s and do
not cover. The same array with control left at 8 bytes is unfed, so class 0
does not cover it.

## 7. Completion word versus FIFO

Detail is [`completion-fifo.md`](completion-fifo.md). The DMA word is
`{reserved[15:0], status[15:0], ticket[31:0]}`, packed from the GEMM result
before the write response. `DmaThenClaim` returns the FIFO status. The word is
proof the ticket landed.

| What failed | Stored word | FIFO and sticky status |
|---|---|---|
| GEMM, including a C-store SLVERR | that GEMM status (1 for `ST_ERR`) | the same status |
| The completion beat itself | GEMM status 0 when the GEMM succeeded. The key survives | `ST_ERR` |

An A-read SLVERR on a job that was eligible to skip B cancels that skip. A
B-read SLVERR after A was already skipped does not read A, returns `ST_ERR`,
and drops A. A completion-beat SLVERR does not drop residency and does not
rewrite a word that already says status 0. QEMU and the virtual card post the
same pair. An oversize guest GEMM writes no C, sets sticky `ST_ERR`, and
stores status 1. On the virtual card a 2×2 INT8 completion-beat failure keeps
C at 19, 22, 43, 50 and a word of status 0.

The engine stays single-outstanding. `CplFifoDepth` is at most 16. A latched
doorbell is held when the engine is busy or the FIFO is full. A newer doorbell
replaces the held ticket. A fetch doorbell clears the hold. A same-cycle
sideband kick still wins, and a zero-pointer sideband kick takes the next free
slot ahead of a held doorbell. The island DMA AXI mux priority is completion
store, then GEMM, then descriptor fetch. When all three are idle the master
drives a zero request and does not accept a response meant for another master.

## 8. Pointer checks, stripe, and the DRAM join

Shared checks in `g6lc_ai_island_cfg_pkg` (`ai_operand_span`,
`ai_elem_aligned`, `ai_c_aligned`, `ai_completion_aligned`) are used by the
descriptor engine, `gemm_seq`, and `g6lc_ai_mem_store`. INT4 packs two
elements per byte. FP16/BF16 are 2 bytes. FP32 is 4. Other live formats are 1
byte. C is packed i32 with `ldc = n` and span `m*n*4`: even `n` needs 8-byte
alignment, odd `n` needs 4-byte alignment. A/B windows are the full AXI load
beat (`BeatBytes = AxiDataWidth/8`, live 8). C stores and the completion word
stay exact sizes. A product that does not fit the address width saturates so
the check fails closed.

`g6lc_ai_gemm_seq` `ST_CHK` returns `ST_ERR` with no new traffic when `m` or
`n` or `k` is 0, when a side is above its accumulator limit, or when `lda < k`
or `ldb < k`. `flags[3]` (`FLAG_REQUANT`) is `ST_BAD_OP` in the descriptor
engine before numeric-format checks. Status codes: `ST_OK=0`, `ST_ERR=1`,
`ST_BAD_VER=2`, `ST_BAD_FMT=8`. Contract version is 2. `OP_LAYOUT` completes
`ST_OK` without GEMM. `FLAG_IRQ` is flags bit 2. CTL bit 1 only gates the
completion DMA store. `ptr_done` is still an 8-byte write probe.

Queue 0 stays at `0x0120`. Later queues start at `0x01A0` with stride `0x20`,
because `0x0140` is the descriptor latch and `0x0180` is the PMU. A region
becomes live when its permission word is written. A job is checked against its
own queue. When `DramChannels > 1` the default stripe is 64 bytes, and a
descriptor pointer that is not 64-byte aligned completes `ST_ERR` and issues
no AR. N=1 accepts a misaligned pointer and issues one 64-byte read.
`AiIslandSimChans2` is the opt-in class-0 two-stripe SRAM. It is not LiteDRAM
and not I2.

`g6lc_ai_dram_join` elaborates only when `G6LC_AI_DRAM_ISLAND_PORT` is set.
Unset, slave[2] stays the 64-bit identity path and the measured ceiling stays
8 bytes/cycle. Set, the island DMA is 512 bits, slave[2] is idle, and the join
narrows the island onto the same 64-bit channel with no second memory map and
no wider core crossbar. The cluster wins a simultaneous address handshake.
An island address outside the DRAM window is `SLVERR`. Island `AxLOCK` and
`ATOP` are forced 0. Wider island data is downsized before the join. Channel
PHYs and class-0 SRAM stay at channel width. Class 2 in
`g6lc_ai_dram_backend` is `gen_no_lpddr5`: `init_done` stays 0, LiteDRAM is
not instantiated, and an initial `$error` reports that LPDDR5 has no PHY.
Class 2 remains an unstarted plan.

A directed class-1 256-beat stream measured 7858 milli-GB/s, 98% of the
64-bit fabric at the 1 GHz accounting. The ≥80% of `min(nameplate, fabric)`
gate is closed on that stream. It is not the 19 GB/s DDR4 nameplate and not
the 16 GB/s class-0 nameplate. More MACs or more DRAM channels do not raise
bytes/cycle on that port. The 400 GB/s figure is DRAM class 2 only.

Island PMU `0x18C` bills A/B reads at `AxiDataWidth/8` and C handshakes at
`min(8, AxiDataWidth/8)`. At 64 bits the two factors match. A C store is not
counted as a 512-bit beat. Nameplate half of CAP `0x18` stays 8 on the live
package.
