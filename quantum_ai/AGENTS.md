# quantum_ai — agent guide

> **Scope.** This subtree is a **self-contained research package**, not part of
> the LibreCore RTL. It contains no SystemVerilog, is not in any elaboration or
> synthesis flow, and is never tier R. The section-0 SoC prime directive in the
> repo-root `AGENTS.md` therefore does not apply here; the licensing discipline
> (§1 below) and the coding philosophy do.

Three artefacts, in dependency order:

```
cycle_function_intuition_thesis_final.pdf   theory of record        (read-only)
  └─ intuition_synthetics/                  worked example of it    (Rust + C ABI)
       └─ quantum_programming_theory/       basis of its C interface (derivation + checks)
```

Read that chain the other way round when changing anything: the derivation
constrains the ABI, and the ABI is what the thesis promises.

## 2. `intuition_synthetics/` — what it is and is not

The runnable form of thesis §4–§6. The **shape of the API is the product**;
the substrate is stubbed on purpose.

| file | role | honest limits |
|---|---|---|
| `include/qrc_full.h` | §4 ABI: `preg_t`/`lreg_t`/`qram_t`, `P_*`, `L_*`, `QRAM_*`, LA helpers | layout is FFI-stable; do not reorder fields |
| `include/qrc_env.h` | §6 intuition layer over `qrc_full.h` | |
| `src/cycle.rs` | the cycle-function primitive | **real-amplitude stub.** `p`/`q` are real and `phase_q` is tracked separately, so `x/z/h` are real-matrix ops and `s/t/rz` only advance `phase_q`. It is not the complex model. |
| `src/qram.rs` | classical stand-in for bucket-brigade qRAM | capacity clamped to `1 << 24` slots to keep the stub bounded |
| `src/intuition.rs` | `EnvWorld`: kernel scoring, top-k query, plan hints, write-back | the "superposition query" is an O(N) scan over occupied slots; the comment in `query()` names the hardware primitives it stands in for |
| `src/ffi.rs` | the C ABI | handles are leaked boxes / ids in a global `Mutex<HashMap>`; `P_H…P_T` are generated by the `preg_gate!` macro, so grepping for `fn P_H` finds nothing |
| `src/tests.rs` | behavioural tests (e.g. `wet_patch_is_avoided`) | |

The scoring kernel is
`K(q,k) ≈ exp(−‖p_q − p_k‖²/2σ²) · (1 − |sin Δyaw|) · (1 − slip) · affordance`,
with `σ = 1.5`; `plan_hint` uses the top 8 hits and picks the highest-affordance
unoccupied one as `next_foothold`, the highest-slip one as `avoid`.

### Gate coverage of the ABI

`qrc_full.h` exposes `H, X, Z, S, T, RZ, CNOT, CZ, Toffoli, Measure` at both the
physical and logical layer. It has **no** `P_Y`, `P_RX`, `P_RY` or `P_SWAP` —
which costs nothing, because the set it does expose already generates the
theory's full 16-gate registry:

```
Rx(θ) = H · Rz(θ) · H          Ry(θ) = S · Rx(θ) · S†
S†    = S³   (S⁴ = I)          Y = i · X · Z          SWAP = three CNOTs
```

So treat them as compositions unless there is a reason (fidelity, pulse count) to
make one primitive. If you do add one, add it to the header, the `preg_gate!`
list and the logical layer together, and say in the commit why composition was
insufficient.

## 3. Humanoid embodiment (`src/anatomy.rs`, `senses.rs`, `motors.rs`, `physiology.rs`, `humanoid.rs`)

A virtual body that feeds the qrc_env/qrc_full runtime. Like the rest of the
package it is simulated, but the wiring from captors through the cervical bus
to motors is explicit.

| module | responsibility | honest limits |
|---|---|---|
| `anatomy.rs` | canonical tables: 20 parts, 11 regions, 24 joints, sensor/motor counts | a configuration file, not a physics solve |
| `senses.rs` | stereo camera with vergence, thermal + touch arrays | no actual image rendering; features are depth bins |
| `motors.rs` | hydraulic-tendon pulley motors, one agonist + antagonist per declared motor | no multi-body dynamics; a 1-DOF per-tendon stub with angular momentum |
| `physiology.rs` | LN2 stator loop, oil rotor loop, zipper ring, cervical star bus | no thermofluid solve; ring is a state machine |
| `humanoid.rs` | tick loop: physiology → sensors → cervical bus → qRAM query → motors | no real quantum co-processor; the query is the same `EnvWorld::plan_hint` used by `qrc_env` |

The C ABI is `qrc_humanoid.h`. Key invariants:

- `qrc_hu_tick` holds the `worlds()` guard for the entire call when an env is
  bound, then the `humanoids()` guard, so the `&EnvWorld` reference passed to
  `Humanoid::tick` stays valid. Do not reverse this lock order.
- The humanoid does **not** own the `EnvWorld`; it stores a handle. This lets a
  `qrc_env` handle stay valid for independent `qrc_env_*` calls.
- `qrc_hu_get_circulation` returns a flat `#[repr(C)]` struct copied from the
  Rust `CirculatorySystem`; keep the two layouts in sync.
- New sensors or motors must have an entry in `anatomy.rs` *before* code assumes
  their existence, because `CaptorBank::new()` and `MotorBank::new()` build from
  the part table.
- The zipper ring behind the neck **blocks all motion and sensing** while open.
  This is the physical safety interlock; `Humanoid::tick` returns early if
  `!zipper.sealed()`.

## 4. `quantum_programming_theory/` — the derivation

Has its own `README.md`. The part that matters to an agent: `js/qtheory.js` is
the **single source of truth** for the physics, and `js/bloch.js` (animated
spheres) and `js/gate-figure.js` (static before/after cards, gate modal, prose
autolinking) only draw. Do not re-derive state maths in a renderer — that is
exactly the drift this layout exists to prevent.

Validate after any change to the model:

```bash
node quantum_programming_theory/test/bloch-vs-quantum-theory.mjs   # 85 checks
```

It builds textbook complex-amplitude QM from scratch as an independent oracle
(unitaries, ρ = |ψ⟩⟨ψ|, Pauli and partial traces, RK4 on the TDSE, Jones vectors,
Stokes parameters), self-checks that oracle first, and is mutation-tested. It
also pins the property that matters for figures: **the rotation arc a figure
draws is the same rotation its table reports.**

`index.html` is generated by `build.py`, but `build.py`'s input attachment is not
in this repo, so it **cannot be regenerated here**. Any change must be applied to
*both* files and kept byte-identical in the overlapping regions — that is how the
CSS, the script tags, the figure blocks and the captions are currently kept in
sync.

## 5. Where the source material contradicts itself

Two reconciliations are implemented in `js/qtheory.js` and documented at its
`orthoAmp()`. They are worth knowing before reading the thesis next to the code,
because the code deliberately does **not** transcribe the thesis's notation.

1. **Pole convention.** The monograph's "Crucial geometric fact" table puts
   vertical polarisation on +Z, while its visual cheat-sheet puts `|0⟩ = sin³` on
   the north pole. The code follows the cheat-sheet, which is also what
   `r_z = P − Q` forces.
2. **The Ortho carrier.** The thesis writes `|ψ⟩ = √P sin³θ + e^{iφ} √Q cos³θ`.
   Taken literally, `cos³` already carries a built-in quarter-cycle stagger, so
   charging a further φ onto it double-counts that quarter cycle and lands linear
   light on ±Y and circular light on ±X — the exact opposite of the monograph's
   own Bloch/Stokes table. `qtheory.js` therefore carries Ortho as
   `√Q sin³(ωt+φ) ≡ √Q cos³(ωt+φ−π/2)`, absorbing the stagger into φ, so φ = 0
   is +45° linear (+X) and φ = ±π/2 is right/left circular (±Y). Verified for all
   six cardinal states against Stokes parameters.

   Corollary: Prime and Ortho are orthogonal **spatial** modes, so they do not
   add as scalars — `√P sin³ + √Q sin³(·+φ)` vanishes identically for −45° linear
   light. Anything summing the two rails is wrong; use the transverse-field
   magnitude `|E| = √(Prime² + Ortho²)`.

`src/cycle.rs` sidesteps this by keeping `phase_q` out of the real rails. If that
stub is ever promoted to a complex model, adopt `qtheory.js`'s convention rather
than the thesis's literal equation.

Also known: the sin³/cos³ language is a *pedagogical overlay*, which the source
thread's own corrigenda states. It reproduces the true polarisation figure's
topology, handedness and cardinal-phase azimuth exactly, but tilts the azimuth by
up to 6.6° at intermediate phases and gives a 50 % `|E|` ripple where real
circular light is constant. Do not present it as Maxwell.

## 6. Verification checklist

Not a hardware flow, so `build.sh verify` does not cover this subtree. Run:

| change | run |
|---|---|
| anything in `js/` or `test/` | `node test/bloch-vs-quantum-theory.mjs` |
| any JS edit | `node --check` on each touched file |
| `build.py` | `python -c "import ast, pathlib; ast.parse(pathlib.Path('build.py').read_text(encoding='utf-8'))"` |
| Rust / C ABI | `cargo test` and `cargo build --release` in `intuition_synthetics/` |
| humanoid module | `cargo test humanoid -- --nocapture` then run `examples/humanoid.rs` |
| new file of any kind | confirm the tier-T header, exactly one SPDX tag |
| `index.html` or `build.py` CSS/scripts/figures | apply to both, then re-serve and confirm no KaTeX errors and no JS exceptions |

`cargo` is available in the current environment; `cargo test` and `cargo run --example humanoid`
should be run after any Rust edit.

## 7. Don'ts

- Don't duplicate physics into a renderer. Extend `js/qtheory.js`.
- Don't edit `index.html` alone when the change belongs in `build.py`'s template
  or CSS, or the next rebuild silently reverts it.
- Don't dump the whole world model per tick in any example or doc — rule 1 and
  rule 2 of §6 of the thesis are the point of the package.
- Don't describe the package as AGI, or the intuition vector as understanding.
  The thesis's §7 exists precisely to refuse that reading, and the docs here
  should keep refusing it.
- Don't reorder or resize fields in `preg_t`, `lreg_t`, `qram_t`, the
  `qrc_env.h` structs, or the new `qrc_humanoid.h` structs: they are published
  FFI layouts consumed from C.
- Don't make `anatomy.rs` tables depend on runtime data. They are `const`
  lookup tables; anything dynamic belongs in the bank instances.
- Don't add a sensor or motor without updating the part table. `CaptorBank` and
  `MotorBank` are built from `PARTS` and `JOINTS` at construction time.
- Two empty placeholder directories exist (`intuition_synthetics/c/`,
  `quantum_programming_theory/css/`). They are untracked-empty and carry no
  meaning yet; don't infer a layout from them.
