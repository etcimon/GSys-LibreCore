# EMIT — the emitter contract

Index: [`README.md`](README.md) · Input: [`IR.md`](IR.md) · Boundary:
[`../AGENTS-licensing.md`](../AGENTS-licensing.md).
Crates: `g6q-emit-args` (B0), `g6q-emit-qemu` (B1/B2), `g6q-vm` (B3).

---

## 1. Universal rules

1. **Input is the `TargetModel`, nothing else.** An emitter that opens a design file has broken the
   architecture. An emitter with a design constant typed into it has broken the *point*.
2. **Text out only.** No emitter links, includes, binds or executes QEMU. Enforced by
   `../tools/check_independence.py`.
3. **Deterministic.** Same model ⇒ byte-identical output. Canonical ordering; no timestamps; the
   model's SHA-256 is the identity stamp.
4. **Banner + SPDX** on every emitted file (§3.1).
5. **Never tracked.** Output goes to `../out/` and `../qemu/`, both gitignored. A hand-edit is lost on
   the next `gen` — fix the emitter.
6. **Idempotent and diffable.** `gen --check` re-emits to a temporary directory and diffs, so CI can
   assert that a checked-in model still produces the expected tree.
7. **One target per emission.** Multi-target output is N invocations into N directories.

## 2. B0 — stock-QEMU driver

Emits **no code**. It composes an invocation of an unmodified `qemu-system-riscv64`:

- a device tree blob, generated from the model or from the design's own tree with overlays applied;
- a `-cpu` property string built from the resolved extension set;
- machine, memory, firmware, kernel, initrd, append, console, drive and network arguments;
- a **capability delta report**.

The delta report is the deliverable, not a footnote. Stock generic machines have a different memory
map, different interrupt-controller geometry, no accelerator device, and no notion of the design's
microarchitectural parameters. B0 states precisely what is *not* under test, which is what makes an
early boot honest rather than misleading.

Emission artifacts: `out/emit/<target>/qemu-args.txt`, `.dtb`, `capability-delta.json`.

## 3. B1 — QEMU machine, CPU and devices

Generated C, targeting the pinned QEMU revision (`../pins.toml`).

| Emitted unit | Contents |
|---|---|
| faithful machine | peripherals with base/length from the model, timer/software-interrupt controller, external interrupt controller with the model's source and context counts, console UART, ROM, DRAM |
| virt machine | the faithful machine plus virtio transports and a configurable RAM window |
| accelerator device | register map, capability window, doorbell, completion path and interrupt line from the model |
| CPU variants | one per target id: extension gating, vendor identification registers, custom CSRs |
| custom instruction translation | decode/translate for any vendor extension the model declares |
| **memory-map self-check** | generated assertions that the constructed machine equals the model |
| build wiring | a makefile / build-system fragment |

### 3.1 Required header

```c
/* DO NOT EDIT — generated by g6lc_qemu <version> from <model sha256>
 * SPDX-License-Identifier: GPL-2.0-or-later
 * This file is part of QEMU (a separate work). The generator that produced it
 * is MIT-licensed and does not link against QEMU.
 */
```

The GPL notice is correct and deliberate: the file *is* part of a GPL work. Emitting an MIT header
into a QEMU tree would be the actual mistake.

### 3.2 The self-check is the point

"Faithful" is a claim until something asserts it. The generated self-check verifies every peripheral
base and length, the interrupt-controller geometry, the memory window including any board-conditional
variant, and the accelerator window and interrupt line — against constants carried in the model from
the design's own SoC package. A machine that drifts fails at construction, not at hour six of a boot.

It asserts only under the faithful profile; under the virt profile it reports the deltas instead.

## 4. B2 — TCG plugins

Three plugins against the pinned plugin API version:

| Plugin | Tier | Emits |
|---|---|---|
| trace | D1 | RVFI-shaped commit records |
| microarchitecture | D2 | predictor / TLB / cache models sized from the model |
| counters | D2 | performance counters, groups and indices from the model's PMU table |

Plugins are preferred over fork-side instrumentation because they need no QEMU source change and have
a stable ABI. Same header and determinism rules as §3.

## 5. B3 — native Rust VM

Not an emitter in the text sense; it *is* the emulator, in this tree, under MIT.

| Tier | Form | When |
|---|---|---|
| T0 | decode-cached threaded interpreter | first; correctness before speed |
| T1 | basic-block JIT with chaining | only if profiling justifies it |
| T2 | region JIT with register promotion | deferred; not required by any gate |

B3 owns what is awkward to bolt onto QEMU: deterministic time, record/replay of memory-mapped I/O and
interrupts keyed on `(hart, retired-instruction-count)`, checkpoint export, and lockstep tandem.

Every instruction, CSR and device behaviour in B3 is **gated on a model field**, never on a literal.
An `if cfg.has_vector` is correct; a `if target == "some-name"` is a defect.

---

## 6. What the emitters must never do

- Open a design file (ingest's job).
- Contain a base address, entry count, event index, opcode or CSR number as a literal.
- Copy source text out of a GPL tree, or derive emitted C by transforming GPL originals — emitted
  files are authored from the model.
- Emit into a tracked directory.
- Special-case a target by name. If behaviour differs, the difference is a model field; if the model
  lacks the field, add it in ingest.
