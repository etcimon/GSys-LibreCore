# AGENTS-licensing — `g6lc_qemu` first-party terms and the GPL-out boundary

Companion to [`AGENTS.md`](AGENTS.md). This file exists because the package **writes GPL-licensed code
without being GPL**, and that only holds if the boundary is stated precisely and enforced
mechanically.

## 2. The GPL-out boundary (`E-GPLLINK`)

QEMU is **GPL-2.0**. This package is MIT. Both facts survive because of one structural rule:

> **The generator writes text. It never links, includes, or imports QEMU.**

| Thing | License | In git? |
|---|---|---|
| The generator (`crates/**`, `tools/**`) | **MIT** | yes |
| C source the generator **emits** (machine, CPU, devices, TCG plugins) | **GPL-2.0-or-later**, authored by the emitter into a **separate work** | **no** — `out/`, `qemu/` are gitignored |
| The QEMU checkout that receives the emission | upstream GPL-2.0, untouched | **no** — fetched on demand, rev in `pins.toml` |
| OpenWrt / Ubuntu distro sources | upstream GPL / Canonical | **dev forks** under `linux-dist/openwrt-*` (etcimon); **compile** uses official OpenWrt + `openwrt/patches/` |
| The native Rust VM (B3) | **MIT** | yes |

### 2.1 Prohibited, without exception

- A `[dependencies]` entry, build script, `bindgen`, `cc`, `pkg-config` probe or `#[link]` attribute
  that reaches QEMU headers or libraries.
- Copying QEMU source into this tree, in whole or in part — including "just this one header" for a
  struct layout. Where a layout is needed, it is described in `architecture/EMIT.md` and emitted, not
  imported.
- Deriving emitted C from QEMU source by transformation. Emitted files must be authored from the
  `TargetModel`, not adapted from GPL originals.
- Tracking emitted C in this repository's history.

### 2.2 Required on every emitted file

```c
/* DO NOT EDIT — generated by g6lc_qemu <version> from <target-model sha256>
 * SPDX-License-Identifier: GPL-2.0-or-later
 * This file is part of QEMU (a separate work). The generator that produced it
 * is MIT-licensed and does not link against QEMU.
 */
```

The GPL notice is correct and deliberate: the emitted file *is* part of a GPL work and must carry GPL
terms. Emitting an MIT header into a QEMU tree would be the actual mistake.

### 2.3 Enforcement

`tools/check_independence.py` fails the build when it finds:

- any `[dependencies]` / `[build-dependencies]` entry that is not a first-party path dependency;
- a `build.rs` anywhere in `crates/**`;
- the tokens `qemu/`, `qemu.h`, `#include`, `bindgen`, `extern "C"` linkage to a foreign library, or
  `#[link` inside `crates/**`;
- any absolute or `../` path escaping the package in a `Cargo.toml`.

The check runs as part of the green command (`python tools/g6q.py check`), so the boundary is a build
failure rather than a review comment.

## 3. Toward the design being read

The generator is **read-only** toward its input tree, and this has a licensing dimension as well as a
correctness one. Input files routinely carry third-party terms — upstream Apache-2.0 / Solderpad RTL,
vendored IP, reciprocal-licensed originals. Therefore:

- **Never edit an input file.** Not a copyright line, not an SPDX identifier, not an attribution or
  `NOTICE`. Retention of those notices is typically a *condition* of the licence the host project
  relies on.
- **Never copy input source into emitted output.** The generator emits *facts* extracted from the
  design (a base address, an entry count, an event index), not source text. Facts about an interface
  are not the expression the licence covers; a copied comment block or a transcribed module body
  would be.
- **Never copy input source into `fixtures/`.** See §4.

## 4. Fixtures are synthetic

`fixtures/` must contain **only content authored for this package**: a miniature config package, a
small flist, a small device tree, and the golden JSON they produce. They are shaped like real inputs
but are not extracts from any project.

Two reasons, both load-bearing:

1. **Licensing.** Copying a config package or flist out of a host project would import that project's
   terms into an MIT tree and would break the "no third-party material here" property.
2. **Independence.** Fixtures are what make `cargo test --workspace` pass with only this tree. If they
   were extracts, the tests would be quietly coupled to a specific upstream revision.

## 5. Third-party Rust dependencies

Currently **none** ([`AGENTS.md`](AGENTS.md) §3). Adding one requires:

1. a recorded decision in `AGENTS-todo.md` (what problem, why not `std`);
2. a `pins.toml` entry with an **exact** version, no floating range, preferring a release published at
   least a week earlier;
3. licence compatibility with MIT outbound — permissive only. **A GPL or LGPL crate is never
   acceptable here**, for the same reason QEMU is kept at arm's length;
4. confirmation that offline `cargo test --workspace` still works for a fresh clone, or an explicit
   note that it no longer does.
