Vol II §8.1 — Ssqosid Extension for Quality-of-Service (QoS) Identifiers

Canonical: specs/riscv-spec.html#ssqosid. Source line: specs/riscv-spec.html:88620. Domain: CACHE.

Ssqosid adds machine/supervisor CSRs that carry a quality-of-service identifier (QoS ID). This ID can be propagated with memory transactions to prioritize or throttle cache/memory bandwidth in interconnects and memory controllers. It is a system-level extension that touches the cache and bus interfaces.

Spec quotation

"Quality of Service (QoS) is defined as the minimal end-to-end performance
guaranteed in advance by a service level agreement (SLA) to a workload.
When multiple workloads execute concurrently on modern processors—
equipped with large core counts, multiple cache hierarchies, and multiple
memory controllers—the performance of any given workload becomes less
deterministic, or even non-deterministic, due to shared resource
contention."
(specs/riscv-spec.html:88620-88628, anchor #ssqosid)

CVA6 status: absent. No QoS ID CSRs (srmcfg/sscfg) are declared in core/csr_regfile.sv and no AXI user-sideband or cache priority signal is driven from the core. Adding Ssqosid would require new CSRs, a QoS ID register in the LSU, and sideband propagation through core/cache_subsystem/ and the AXI adapter.

.dts linkage: no DT node; Ssqosid would be advertised through the riscv,isa string or SoC interconnect QoS properties if implemented.
