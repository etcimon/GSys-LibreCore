Vol II §4.5 — Sv48: Page-Based 48-bit Virtual-Memory System

Canonical: specs/riscv-spec.html#sv48. Domain: RAM.

Sv48 extends Sv39 by adding a fourth page-table level, supporting 48-bit virtual addresses while keeping 4 KiB pages. It is intended for systems for which a 39-bit virtual address space is insufficient. Implementations that support Sv48 must also support Sv39.

Spec quotation

"This section describes a simple paged virtual-memory system for
SXLEN=64, which supports 48-bit virtual address spaces. Sv48 is intended
for systems for which a 39-bit virtual address space is insufficient. It
closely follows the design of Sv39, simply adding an additional level of
page table, and so this chapter only details the differences between the
two schemes. Implementations that support Sv48 must also support Sv39."
(specs/riscv-spec.html:79597-79611, anchor #sv48 / #norm:Sv48_sxlen)

CVA6 status: configurable. The mode enum includes ModeSv48 = 9 at core/include/config_pkg.sv:49, and the MMU/PTW is parameterized by PtLevels, VpnLen, and PPNW so the extra page-table level is generated at elaboration (core/cva6_mmu/cva6_ptw.sv:120-200). Most shipped 64-bit targets set MODE_SV = ModeSv39, so Sv48 is build-time selectable but not the default.

.dts linkage: if a target selects Sv48, the CPU node mmu-type must report riscv,sv48 and the memory@ map must cover the larger physical address space.
