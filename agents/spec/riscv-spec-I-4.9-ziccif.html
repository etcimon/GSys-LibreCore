Vol I §4.9 — Ziccif Extension for Instruction-Fetch Atomicity

Canonical: specs/riscv-spec.html#ext:ziccif. Domain: RAM.

Ziccif requires that aligned instruction fetches are atomic: an instruction fetch must return a single value corresponding to one of the writes to that location, never a torn combination of multiple writes. It underpins self-modifying code and I-cache/D-cache coherence: without atomic instruction fetches, FENCE.I would not have a well-defined value to observe.

Spec quotation

"If the Ziccif extension is implemented, main memory regions with both the
coherence and cacheability PMAs must support instruction fetch, and any
instruction fetches of naturally aligned power-of-2 sizes of at most
min(ILEN, XLEN) bits are atomic."
(specs/riscv-spec.html:10542-10550, anchor #norm:ziccif_if_atomicity)

Pseudo-SystemVerilog synthesis notes

module ziccif_fetch_buffer (
  input  logic [XLEN-1:0] paddr_i,
  input  logic [ILEN-1:0] data_i,
  output logic [ILEN-1:0] instr_o
);
  // aligned ILEN-wide fetch is atomic; no cross-write tearing visible
endmodule

CVA6 status: implemented/partial; instruction fetches are always aligned to a 32-bit or 64-bit boundary (core/cache_subsystem/g6lc_icache.sv:22,65-113; selected word cl_sel at :113) and refill a whole cache line atomically before the line becomes valid (core/cache_subsystem/g6lc_icache.sv:319-321). core/frontend/frontend.sv:149,312-313,318-321 gates fetches during halt_frontend_i and kills speculative fetches on flush_i, preventing stale data from being consumed. Full Ziccif conformance over main-memory PMA regions has not been documented as a separately verified artifact.

.dts linkage: the memory@ nodes for cacheable instruction regions must keep cacheable PMAs aligned with NrCachedRegionRules/CachedRegionAddrBase/CachedRegionLength in core/include/config_pkg.sv; only those regions are guaranteed to provide atomic instruction fetches.
