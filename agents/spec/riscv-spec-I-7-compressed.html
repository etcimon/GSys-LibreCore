Vol I chapter 7 — Compressed Instructions

Canonical anchors: #ext:c (7.4 C), #ext:zca (7.1 Zca), #ext:zcf (7.2 Zcf), #ext:zcd (7.3 Zcd), #ext:zcb (7.5 Zcb), #ext:zcmt (7.6 Zcmt). Source lines: specs/riscv-spec.html:18213 (Zca), :19846 (C).

Spec quotation

"This section describes the C extension, which incorporates the
compressed instruction-set extensions designed for application- and
server-class processors. The C extension substantially improves code
density across a wide range of applications, thereby improving
performance, area-efficiency, and energy-efficiency of processors with
instruction caches. It excludes features that improve code density at
the cost of performance."
(specs/riscv-spec.html:19846-19853, anchor #ext:c)

The C extension encodes common 32-bit instructions in 16-bit formats, halving code size. It adds compressed load/store, branches, jumps, arithmetic, and floating-point operations. The frontend must expand 16-bit instructions to 32-bit equivalents before decode; expansion must preserve original register specifiers and immediate values. C interacts with branch prediction because a fetch packet may contain a mixture of 16- and 32-bit instructions, and the PC advance must be computed per instruction.

CVA6 status: implemented when CVA6Cfg.RVC is set. The 16-bit instruction expansion is in core/compressed_decoder.sv:22-. The expanded instruction is passed to the decoder, which preserves the original 16-bit form for exception reporting at core/decoder.sv:1849-1852. The issue stage records the compressed flag at core/issue_read_operands.sv:158,1043-1055,1087 and propagates it to the branch unit and ex stage (core/branch_unit.sv:37, core/ex_stage.sv:58). The PC advance in the frontend handles mixed 16/32-bit packets.

.dts linkage: the CPU riscv,isa string contains C when RVC is enabled; this must match CVA6Cfg.RVC.
