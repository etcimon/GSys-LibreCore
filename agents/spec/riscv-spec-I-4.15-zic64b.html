Vol I §4.15 — Zic64b Extension for 64-byte Cache Blocks

Canonical: specs/riscv-spec.html#ext:zic64b (source line 10978). Domain: CACHE.

The normative requirement, quoted from specs/riscv-spec.html:10978-10981, is: "If the Zic64b extension is implemented, then cache blocks must be 64 bytes in size, naturally aligned in the address space." This fixes the line width for both the in-core L1 caches and any external L2/L3, and it constrains CMO block operations and block-size device-tree properties.

CVA6 status: not implemented by current targets, though the cache line width is parameterised. The parameter fields are IcacheLineWidth and DcacheLineWidth in core/include/config_pkg.sv:184,194; defaults are supplied by core/include/ariane_pkg.sv:226,238 as CONFIG_L1I_CACHELINE_WIDTH 128 and CONFIG_L1D_CACHELINE_WIDTH 128 (16 bytes). All active target packages (e.g. core/include/cv64a6_imafdc_sv39_config_pkg.sv:42,45 and core/include/cv64a6_imafdcv_sv39_config_pkg.sv:44,47) set 128- or 256-bit lines (16 or 32 bytes), so no shipped configuration satisfies the 64-byte block requirement. Raising DcacheLineWidth and IcacheLineWidth to 512 bits (64 bytes) would be the tape-out integration path.

.dts linkage: i-cache-block-size and d-cache-block-size in bytes derive from IcacheLineWidth/8 and DcacheLineWidth/8. With current defaults both are 16 bytes; a Zic64b-compliant target must report 64.
