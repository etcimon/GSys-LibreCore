Vol II §6.9 — Control-Flow Integrity (CFI)

Canonical: specs/riscv-spec.html#priv-cfi. Source line: specs/riscv-spec.html:86912. Domain: BP.

The privileged CFI chapter defines the machine-mode controls for the unprivileged CFI extension: landing-pad enable bits, shadow-stack pointer CSRs (mssp, ssp), and the privileged rules for indirect forward-edge and return-edge checks. It governs how CFI integrates with privilege modes and traps.

Spec quotation

"Control-flow integrity (CFI) capabilities help defend against Return-
Oriented Programming (ROP) and Call/Jump-Oriented Programming (COP/JOP)
style control-flow subversion attacks. The Zicfiss and Zicfilp
extensions provide backward-edge and forward-edge CFI respectively."
(specs/riscv-spec.html:86912-86917, anchor #priv-cfi)

CVA6 status: absent. The core/csr_regfile.sv does not define the privileged CFI CSRs (menvcfg.LPE, mssp/ssp), and the decoder/branch unit in core/decoder.sv/core/branch_unit.sv does not perform landing-pad or shadow-stack checks. This requires paired work with the unprivileged CFI sub-file (riscv-spec-I-4.17-cfi.html).

.dts linkage: no DT node; privileged CFI would be advertised in the riscv,isa string and the menvcfg CSR description if implemented.
