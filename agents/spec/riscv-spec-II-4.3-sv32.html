Vol II §4.3 — Sv32: Page-Based 32-bit Virtual-Memory Systems

Canonical: specs/riscv-spec.html#sv32. Domain: RAM.

Sv32 is the 32-bit paging mode. When Sv32 is written to the satp MODE field, the supervisor operates in a 32-bit paged virtual-memory system; supervisor and user virtual addresses are translated into supervisor physical addresses by traversing a radix-tree page table. Sv32 is supported when SXLEN=32. It uses 4 KiB pages, a 20-bit VPN, and a two-level page table with 4-byte PTEs; leaf and superpage rules mirror the 64-bit modes.

Spec quotation

"When Sv32 is written to the MODE field in the satp register, the
supervisor operates in a 32-bit paged virtual-memory system. In this
mode, supervisor and user virtual addresses are translated into
supervisor physical addresses by traversing a radix-tree page table.
Sv32 is supported when SXLEN=32 and is designed to include mechanisms
sufficient for supporting modern Unix-based operating systems."
(specs/riscv-spec.html:78849-78859, anchor #sv32)

CVA6 status: implemented when selected. The legal mode enumeration is in core/include/config_pkg.sv:45-52 (vm_mode_t with ModeSv32 = 1); the MMU/PTW is instantiated in core/cva6.sv:1065-1096 and the walker is in core/cva6_mmu/cva6_ptw.sv:23-, parametrized by CVA6Cfg.PtLevels, VpnLen, and PPNW. The 32-bit target packages set MODE_SV = ModeSv32 (e.g. core/include/cv32a6_imac_sv32_config_pkg.sv) and the satp PPN comes from core/csr_regfile.sv.

.dts linkage: the CPU node mmu-type must be riscv,sv32 for 32-bit CVA6 targets; it must match the configured vm_mode_t and the satp MODE field.
