Vol II §3.4 — Reset

Canonical: specs/riscv-spec.html#reset. Source line: specs/riscv-spec.html:75843. Domain: —.

Reset initializes the hart to a defined architectural state: pc set to the reset vector, privilege mode M, and all CSRs to specified initial values. It is the bootstrap contract that makes the rest of the machine-mode ISA deterministic. Any feature addition must preserve these reset values and vector.

Spec quotation

"Upon reset, a hart's privilege mode is set to M. The mstatus fields
MIE and MPRV are reset to 0. If little-endian memory accesses are
supported, the mstatus/mstatush field MBE is reset to 0. The misa
register is reset to enable the maximal set of supported extensions. For
implementations with the Zalrsc standard extension, there is no valid
load reservation. The pc is set to an implementation-defined reset
vector. The mcause register is set to a value indicating the cause of
the reset."
(specs/riscv-spec.html:75843-75857, anchor #reset)

Pseudo-SystemVerilog synthesis notes

module reset_unit (
  input  logic        rst_ni,
  input  logic [XLEN-1:0] reset_vector_i,
  output logic [XLEN-1:0] boot_addr_o,
  output priv_lvl_e   priv_o
);
  // on reset deassert: pc <= reset_vector; priv <= M
endmodule

CVA6 status: implemented. The reset vector is supplied as boot_addr_i to core/frontend/frontend.sv and to the core top-level in core/cva6.sv. CSR reset values and the M privilege level are established in core/csr_regfile.sv. The cache/TLB reservation state is invalidated on reset in the LR/SC tracker. The reset strategy is asynchronous-active-low rst_ni pervasive throughout the core (core/cva6_fifo_v3.sv:207-213).

.dts linkage: the SoC device tree defines the boot/reset vector via the memory@ / boot ROM and the CPU node status = "okay"; the chosen boot arguments must match the reset vector configuration.
