Vol III §1 — Introduction

Canonical anchors: #_profiles_versus_platforms (1.1), #_components_of_a_profile (1.2), #_rva_profiles_rationale (1.3). Source line: specs/riscv-spec.html:89579 (1.1).

Volume III defines RISC-V Profiles, which are named, versioned, and platform-agnostic sets of ISA extensions. Profiles separate the profile itself (the ISA contract) from the platform (the SoC environment). Components of a profile include the base ISA, standard extensions, privileged architecture version, and optional extensions. Profiles serve as the conformance target for software and as a checklist for hardware configuration and device-tree ISA strings.

Spec quotation

"Profiles only describe ISA features, not a complete execution
environment. A software platform is a specification for an execution
environment, in which software targeted for that software platform can
run."
(specs/riscv-spec.html:89579-89587, anchor #_profiles_versus_platforms)

CVA6 status: not a hardware feature. Each per-target config package in core/include/cv*a6*_config_pkg.sv selects a concrete set of extension bits (RVA/RVC/RVF/RVD/RVB/ZKN/RVZiCond, etc.). The profile membership is derived from those bits and should be cross-checked against the riscv,isa string in the generated device tree.

.dts linkage: the CPU riscv,isa string is the profile advertisement; it must be consistent with CVA6Cfg. For example, a RVA20U64 configuration should yield rv64imafdc_zicsr_zifencei or equivalent.
