Vol I §5.5 — Zawrs Extension for Wait-on-Reservation-Set Instructions

Canonical: specs/riscv-spec.html#ext:zawrs (source line 14761). Domain: SPEC.

WRS.NT and WRS.STO allow software to pause execution until either the LR reservation is lost or a timeout occurs, enabling low-power polling loops. The Zawrs extension defines a pair of WRS (wait-on-reservation-set) instructions to be used in polling loops that allows a core to enter a low-power state and wait on a store to a memory location. The instructions are architecturally defined as spin-loop hints and do not change architectural state.

CVA6 status: partial (config) — U7ᵇ. When CVA6Cfg.ZawrsEn is set, core/decoder.sv decodes WRS.NTO / WRS.STO (SYSTEM funct3=0, imm 0x00d / 0x01d) and maps them onto the existing WFI wait path in core/csr_regfile.sv (TW/VTW privilege checks shared with WFI). Enabled on primary cv64a6_imafdc_sv39 and HPDCACHE targets. Gaps vs full Zawrs: no reservation-set loss detector (wake is interrupt/timeout-class only), STO timeout is not a distinct microarch timer, and there is no dedicated low-power clock gate (U8ᵇ).

.dts linkage: advertise zawrs in riscv,isa-extensions when enabled; may later pair with idle-state DT if U8 power management lands.
