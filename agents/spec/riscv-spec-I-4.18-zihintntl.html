Vol I §4.18 — Zihintntl Extension for Non-Temporal Locality Hints

Canonical: specs/riscv-spec.html#ext:zihintntl. Domain: CACHE.

Zihintntl adds NTL instructions as HINTs that indicate the explicit memory accesses of the immediately subsequent instruction exhibit poor temporal locality. They do not change architectural state or the architecturally visible effects of the target instruction. Four variants target the innermost private cache, any private cache, the innermost shared cache, and all shared caches. They affect cache allocation policy and prefetchers but are not functional correctness requirements.

Spec quotation

"The NTL instructions are HINTs that indicate that the explicit memory
accesses of the immediately subsequent instruction (henforth `target
instruction') exhibit poor temporal locality of reference. The NTL
instructions do not change architectural state, nor do they alter the
architecturally visible effects of the target instruction."
(specs/riscv-spec.html:12157-12163, anchor #ext:zihintntl / #norm:NTL_target_definition)

CVA6 status: absent. No NTL decoding exists in core/decoder.sv, no non-temporal load/store type is carried through the LSU/scoreboard, and the D$/HPDcache allocation logic does not consult a temporal-locality hint. All current target packages leave RVZiCbom enabled where applicable, but there is no equivalent RVZihintntl bit.
