Vol II §7.6 — Svrsw60t59b Extension for PTE Reserved-for-Software Bits 60-59

Canonical: specs/riscv-spec.html#ext:svrsw60t59b. Domain: RAM.

Svrsw60t59b reserves PTE bits 60-59 for software use and requires hardware to ignore them during translation. If the Svrsw60t59b extension is implemented, bits 60-59 of the page table entries (PTEs) are reserved for use by supervisor software and are ignored by the implementation. The OS can use these bits for metadata (e.g. swap or reference tracking) without affecting the page-table walker.

Spec quotation

"If the Svrsw60t59b extension is implemented, then bits 60-59 of the
page table entries (PTEs) are reserved for use by supervisor software
and are ignored by the implementation."
(specs/riscv-spec.html:88567-88570, anchor #ext:svrsw60t59b / #norm:Svrsw60t59b_reserved_bits_60_59)

Pseudo-SystemVerilog synthesis notes

module svrsw60t59b_mask (
  input  logic [63:0] pte_i,
  output logic [63:0] pte_masked_o
);
  // mask off bits 60:59 before using PTE for translation
endmodule

CVA6 status: absent. The page-table walker in core/cva6_mmu/cva6_ptw.sv reads the full PTE from memory at :104 and uses it directly for permission/type checks (e.g. :279-294) and PPN extraction (e.g. :175-198) without masking bits 60-59. If those bits are set by software, the walker may interpret them as part of the PPN or as reserved bits and raise a page fault. A future Svrsw60t59b implementation would add a constant mask {pte[63:61], 2'b00, pte[58:0]} or equivalent before the PTE validation logic.

.dts linkage: no DT node; Svrsw60t59b depends on Sv39 and would be exposed through the mmu-type or an extension string for 64-bit CVA6 targets.
