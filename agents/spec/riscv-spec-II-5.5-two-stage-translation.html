Vol II §5.5 — Two-Stage Address Translation

Canonical: specs/riscv-spec.html#two-stage-translation. Source line: specs/riscv-spec.html:82075. Domain: RAM.

Two-stage translation is the hypervisor extension (H) feature that translates a guest virtual address (GVA) first to a guest physical address (GPA) using guest page tables (vsatp), then to a machine physical address using host page tables (hgatp). It is required for virtualizing operating systems and adds significant MMU complexity: the combined GPA- and second-stage page-fault handling, access-bit updating, and TLB tagging with VMID/ASID.

Spec quotation

"Whenever the current virtualization mode V is 1, two-stage address
translation and protection is in effect. For any virtual memory access,
the original virtual address is converted in the first stage by VS-level
address translation, as controlled by the vsatp register, into a guest
physical address. The guest physical address is then converted in the
second stage by guest physical address translation, as controlled by the
hgatp register, into a supervisor physical address."
(specs/riscv-spec.html:82075-82084, anchor #two-stage-translation)

CVA6 status: absent. The H extension is not implemented. The MMU in core/cva6_mmu/ performs only single-stage translation. Adding two-stage translation would require a nested PTW, TLB tagging with VMID, and the H-mode CSR state.
