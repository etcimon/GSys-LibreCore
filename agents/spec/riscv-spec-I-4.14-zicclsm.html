Vol I §4.14 — Zicclsm Extension for Main Memory Misaligned Accesses

Canonical: specs/riscv-spec.html#ext:zicclsm. Domain: RAM.

Zicclsm guarantees that misaligned loads and stores to main memory are supported without generating an address-misaligned exception. Without it, the implementation may trap on misaligned accesses. This is a main-memory attribute that interacts with the LSU and the PMA checker: if the extension is not present, the LSU must split or trap; if present, the memory system must handle subword/unaligned accesses.

Spec quotation

"If the Zicclsm extension is implemented, then misaligned loads and stores
to main memory regions with both the coherence and cacheability PMAs must be
supported."
(specs/riscv-spec.html:10942-10946, anchor #ext:zicclsm / #norm:zicclsm_misaligned_support)

Pseudo-SystemVerilog synthesis notes

module zicclsm_lsu (
  input  logic [XLEN-1:0] addr_i,
  input  logic [2:0]      size_i,     // 1/2/4/8 bytes
  output logic            misaligned_o,
  output logic [XLEN-1:0] addr_lo_o, addr_hi_o
);
  // if Zicclsm present: split access; otherwise raise misaligned
endmodule

CVA6 status: absent. CVA6 does not split misaligned loads or stores in hardware. Detection is performed in core/load_store_unit.sv:176-177,244,720-762; when the address does not satisfy the access-size alignment, data_misaligned is asserted and the LSU raises LD_ADDR_MISALIGNED (load, :767-768) or ST_ADDR_MISALIGNED (store, :779-780) through the MMU. Software emulation or a trap handler is required to complete the access. Enabling Zicclsm would require a hardware splitter in the LSU and write-buffer, plus PMA gating so that misaligned access support is advertised only for coherent-cacheable main-memory regions.

.dts linkage: a Zicclsm-compliant CVA6 would advertise riscv,unaligned-access (or a profile-specific property) and ensure the corresponding memory@ nodes are marked cacheable/coherent; current configurations leave the property unset because hardware does not split.
