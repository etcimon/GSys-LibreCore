Vol I §5.10 — Zama16b Extension for 16-byte Misaligned Atomicity

Canonical: specs/riscv-spec.html#ext:zama16b. Domain: RAM.

Zama16b guarantees that 16-byte atomic memory operations are atomic even when the 16-byte object is not aligned to a 16-byte boundary. If Zama16b is implemented, the misaligned atomicity granule in main memory regions with both the coherence and cacheability PMAs is 16 bytes; misaligned loads, stores, and AMOs to those regions that do not cross a naturally aligned 16-byte boundary are atomic.

Spec quotation

"If the Zama16b extension is implemented, then the misaligned atomicity
granule in main memory regions with both the coherence and cacheability
PMAs is 16 bytes. Misaligned loads, stores and AMOs to those regions
that do not cross a naturally aligned 16-byte boundary are atomic."
(specs/riscv-spec.html:15483-15486, anchor #ext:zama16b / #norm:zama16b_mag)

CVA6 status: absent. CVA6 has no 128-bit AMO/CAS datapath: the amo_t enum in core/include/ariane_pkg.sv:361-373 is limited to word/doubleword operations, core/decoder.sv:1602-1647 does not decode 16-byte AMOs, and core/cache_subsystem/amo_alu.sv:14-65 operates on 64-bit operands. There is no 128-bit load/store/AMO port in the LSU or cache subsystem, and no misaligned-16-byte atomicity mechanism in core/load_store_unit.sv. Adding Zama16b would require a 128-bit AMO datapath, cross-bank atomic write masking, and either a locked AXI transaction or HPDcache support for 16-byte atomic RMW.

.dts linkage: no DT node currently; Zama16b would be advertised through the riscv,isa string and would require memory@ nodes with both coherence and cacheability PMAs.
