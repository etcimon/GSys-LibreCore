Vol I §4.1 — Zifencei Extension for Instruction-Fetch Fence

Canonical: specs/riscv-spec.html#ext:zifencei (source line 8880). Domain: BP, SPEC, CACHE.

FENCE.I provides explicit synchronization between writes to instruction memory and instruction fetches on the same hart. The execution rule is that a program must execute a FENCE.I after storing to instruction memory and before fetching those stores as instructions. This directly affects the frontend: the pipeline must flush or stall the instruction fetch and invalidate or refetch from the I$ so that stale instructions are not executed. It is the canonical interface between stores and the predictor/fetch unit.

Spec quotation

"This chapter defines the Zifencei extension, which includes the FENCE.I
instruction that provides explicit synchronization between writes to
instruction memory and instruction fetches on the same hart. Currently,
this instruction is the only standard mechanism to ensure that stores
visible to a hart will also be visible to its instruction fetches."
(specs/riscv-spec.html:8880-8888, anchor #ext:zifencei)
