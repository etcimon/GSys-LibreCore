Vol II §6.7 — Smdbltrp Double Trap Extension

Canonical: specs/riscv-spec.html#smdbltrp. Source line: specs/riscv-spec.html:85529. Domain: SPEC.

Smdbltrp defines the behavior when a trap occurs while the hart is already handling a previous trap in the same privilege mode. It introduces a double-trap state and recovery mechanism, preventing unrecoverable state corruption. The implementation must detect the condition and enter a safe debug or reset path.

Spec quotation

"The Smdbltrp extension addresses a double trap in M-mode. When the
Smrnmi extension is implemented, it enables invocation of the RNMI
handler on a double trap in M-mode to handle the critical error. If the
Smrnmi extension is not implemented or if a double trap occurs during
the RNMI handler's execution, this extension helps transition the hart
to a critical error state and enables signaling the critical error to
the platform."
(specs/riscv-spec.html:85529-85537, anchor #smdbltrp)

CVA6 status: absent. There is no double-trap detection state machine in core/controller.sv and no mstatus.MDT or mcause critical-error reporting. A second trap taken during M-mode trap handling would overwrite the M-mode trap CSRs in the normal update path.

.dts linkage: no DT node; Smdbltrp would be advertised in the riscv,isa string if implemented.
