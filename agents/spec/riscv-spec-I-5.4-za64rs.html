Vol I §5.4 — Za64rs Extension for Reservation-Set Size

Canonical: specs/riscv-spec.html#ext:za64rs. Domain: RAM.

Za64rs guarantees a maximum LR/SC reservation-set size of 64 bytes. The Za64rs extension requires that the reservation sets used by the instructions in the Zalrsc extension be contiguous, naturally aligned, and at most 64 bytes in size. This is the common case when combined with Zic64b (64-byte cache blocks), because the reservation is naturally bounded by the cache-line size.

Spec quotation

"The Za64rs extension requires that the reservation sets used by the
instructions in the Zalrsc extension be contiguous, naturally aligned,
and at most 64 bytes in size."

CVA6 status: not guaranteed. CVA6 does not implement a 64-byte reservation-set guarantee explicitly. The LR/SC path is in core/load_store_unit.sv:728-748, core/store_unit.sv:134-135,282-319, and the cache subsystem (WT core/cache_subsystem/wt_dcache_missunit.sv:334-347,576-583; HPDcache core/cache_subsystem/hpdcache/rtl/src/hpdcache_ctrl.sv:157-161,1179-1181). The effective reservation set is bounded by the cache-line size, but shipped targets use DcacheLineWidth of 128 or 256 bits (16 or 32 bytes) in core/include/config_pkg.sv, not 64 bytes, and Zic64b is not satisfied. Therefore Za64rs is not currently advertised and should not be claimed in the ISA string.

.dts linkage: no DT node; Za64rs would be exposed through riscv,isa only when the reservation-set size and cache-line width are both raised to at least 64 bytes and verified.
