Vol II §6.10 — Pointer Masking Extensions

Canonical: specs/riscv-spec.html#Zpm. Source line: specs/riscv-spec.html:87492. Domain: RAM.

The Zpm pointer-masking extensions allow software to store metadata in the upper bits of pointers by masking those bits during memory-address generation. The mask is configurable per privilege mode through CSRs. It relaxes the usual sign-extension/canonicality rules for effective addresses.

Spec quotation

"RISC-V Pointer Masking (PM) is a feature that, when enabled, causes the
CPU to ignore the upper bits of the effective address. This allows these
bits to be used in whichever way the application chooses. Such tools can
be applied in all privilege modes (U, S, and M)."
(specs/riscv-spec.html:87492-87497, anchor #Zpm)

CVA6 status: absent. No pointer-masking CSRs (mpmmask, spmmask, etc.) are implemented in core/csr_regfile.sv, and the LSU/MMU in core/load_store_unit.sv/core/cva6_mmu/ does not mask upper address bits before translation.
