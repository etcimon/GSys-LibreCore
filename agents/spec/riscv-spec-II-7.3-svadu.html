Vol II §7.3 — Svadu Extension for Hardware Updating of A/D Bits

Canonical: specs/riscv-spec.html#ext:svadu. Source line: specs/riscv-spec.html:88370. Domain: RAM.

Svadu permits the hardware to set the accessed (A) and dirty (D) bits in page-table entries automatically during translation and writeback, rather than requiring software emulation via page faults. This reduces OS overhead but requires atomic PTE updates and careful ordering with stores and with the memory model.

Spec quotation

"The Svadu extension adds support and CSR controls for hardware updating
of PTE A/D bits. If the Svadu extension is implemented, the
menvcfg.ADUE field is writable."
(specs/riscv-spec.html:88370-88374, anchor #ext:svadu)

Pseudo-SystemVerilog synthesis notes

module svadu_pte_update (
  input  logic [63:0] pte_i,
  input  logic        access_i, store_i,
  output logic [63:0] pte_o,
  output logic        pte_write_o
);
  // set A on any successful translation; set D on write; write PTE atomically
endmodule

CVA6 status: absent. The page-table walker in core/cva6_mmu/cva6_ptw.sv reads PTEs but does not write back updated A/D bits. Adding Svadu requires an atomic read-modify-write path to memory for PTE updates, ordering with the store buffer, and the menvcfg.ADUE CSR in core/csr_regfile.sv.

.dts linkage: no DT node; Svadu would be advertised in the riscv,isa string (e.g. _svadu) if implemented.
