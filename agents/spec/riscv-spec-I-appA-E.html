Vol I Appendices A-E

Canonical anchors: #rv32-64g (A), #app:mm (B), #app:naming (C), #app:code-examples (D), #app:rationale (E). Source lines: specs/riscv-spec.html:57084 (A), :60295 (B), :65697 (C), :66113 (D), :67042 (E).

Appendix A is the RV32/64G instruction listing (opcode table). Appendix B is a memory-model supplement with litmus tests and formal-model references (domain SPEC). Appendix C defines core naming and extension-name conventions. Appendix D lists raw opcode spaces. Appendix E describes historical rationale for extensions. These are mostly reference material; only Appendix B has implementation relevance for memory-model verification and Appendix C for ISA-string construction.

CVA6 status: reference. Appendix A/D/E have no dedicated hardware; the encodings are implemented by core/decoder.sv and the opcode/CSR tables. Appendix B memory-model supplement is exercised by verif/regress/ litmus tests and formal/RTL simulation. Appendix C naming conventions determine how the riscv,isa string and CVA6 config/RTL extension bits are presented to software.

.dts linkage: the CPU node riscv,isa and mmu-type strings are built using the Appendix C naming rules; e.g. rv64imafdc_zicsr_zifencei. Appendix B guides memory-ordering tests that verify the memory@ and soc node attributes are consistent with the implemented PMA/RVWMO model.
