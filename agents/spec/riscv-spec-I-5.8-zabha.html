Vol I §5.8 — Zabha Extension for Byte and Halfword Atomic Memory Operations

Canonical: specs/riscv-spec.html#ext:zabha. Domain: RAM.

Zabha extends AMOs to byte and halfword operands (AMOSWAP.B/H, AMOADD.B/H, etc.). The Zaamo and Zacas extensions offer AMO instructions for words, doublewords, and quadwords (only for AMOCAS). The absence of atomic operations for subword data types necessitates emulation strategies; Zabha fills that gap. It requires the memory system to provide atomic read-modify-write at subword granularities without corrupting neighboring bytes.

CVA6 status: absent. The AMO opcode space in core/decoder.sv:1602-1647 only decodes word/doubleword AMO and LR/SC variants; the amo_t enum in core/include/ariane_pkg.sv:361-373 has no byte/halfword AMO operations, and core/cache_subsystem/amo_alu.sv:14-65 operates on full 64-bit operands with no subword masking or sign-extension path. Extending Zabha would require new decode slots, a subword operand align/mask unit in the LSU/store unit, and either byte-masked cache writes or locked read-modify-write bus transactions.

.dts linkage: no DT node; Zabha capability would be added to the riscv,isa string and requires cacheable/coherent memory@ regions with subword atomic support.
