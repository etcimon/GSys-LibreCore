Vol II §6.6 — Smcdeleg and Ssccfg Counter Delegation Extensions

Canonical: specs/riscv-spec.html#smcdeleg. Source line: specs/riscv-spec.html:85274. Domain: —.

Smcdeleg/Ssccfg allow M-mode to delegate control of performance-counter event selection and filtering to S-mode. This supports OS-level profiling without M-mode intervention for every counter configuration change.

Spec quotation

"In modern 'Rich OS' environments, hardware performance monitoring
resources are managed by the kernel, kernel driver, and/or hypervisor.
Counters may be configured with differing scopes ... In such
environments, the latency of counter writes has a direct impact on
overall profiling overhead."
(specs/riscv-spec.html:85274-85280, anchor #smcdeleg)

Pseudo-SystemVerilog synthesis notes

module counter_delegation (
  input  logic [XLEN-1:0] mcountinhibit_i, sscfg_i,
  input  logic            delegate_i,
  output logic [XLEN-1:0] effective_config_o
);
  // S-mode controls counters delegated by M-mode
endmodule

CVA6 status: absent. Counter access control in core/csr_regfile.sv does not delegate mhpmevent or counter-filter CSRs to S-mode; there is no scountercfg/mcountercfg delegation path.

.dts linkage: no DT node; Smcdeleg/Ssccfg are CSR behavior extensions with no direct device-tree property.
