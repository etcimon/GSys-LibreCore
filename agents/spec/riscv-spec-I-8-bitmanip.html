Vol I chapter 8 — Bit-Manipulation Extensions

Canonical anchors: #ext:zba (8.1 Zba), #ext:zbb (8.2 Zbb), #ext:zbc (8.3/8.5 Zbc), #ext:zbs (8.4 Zbs), #ext:zicond (4.7 Zicond). Source lines: specs/riscv-spec.html:23438 (Zba), :23519 (Zbb), :23894 (Zbs), :23975 (Zbc), :10063 (Zicond).

The B/Zb* extensions add bit manipulation, carry-less multiply, conditional move/zero, and address-generation shifts. They are pure integer ISA additions and map directly to the integer ALU and multiplier. Zba/Zbb/Zbs are the most common profile requirements. Zicond is the integer conditional-move/zero extension.

Spec quotation

"The Zba instructions can be used to accelerate the generation of
addresses that index into arrays of basic types (halfword, word,
doubleword) using both unsigned word-sized and XLEN-sized indices: a
shifted index is added to a base address."
...
"The single-bit instructions provide a mechanism to set, clear, invert,
or extract a single bit in a register. The bit is specified by its index."
(specs/riscv-spec.html:23438-23440 anchor #ext:zba; :23896-23898 anchor #ext:zbs)

Pseudo-SystemVerilog synthesis notes

module bitmanip_alu (
  input  logic [XLEN-1:0] a_i, b_i,
  input  bmu_op_e         op_i,    // Zba/Zbb/Zbc/Zbs/Zicond
  output logic [XLEN-1:0] result_o
);
  // barrel shifter, clz/ctz/pcnt, min/max, and/ior/xor, carry-less mul
endmodule

CVA6 status: partially implemented. The CVA6Cfg.RVB bit gates bit-manipulation operations in core/alu.sv (Zba/Zbb/Zbs logic) and core/multiplier.sv:49-52,137- (carry-less multiply Zbc). The CVA6Cfg.RVZiCond bit selects conditional-zero/move operations in the ALU. The decoder classifies the operations and the issue stage routes them to the ALU/multiplier fixed-latency unit. Coverage of every Zbb/Zbs/Zbc instruction should be verified against the spec encoding tables.

.dts linkage: the CPU riscv,isa string advertises _zba, _zbb, _zbs, _zbc, and/or _zicond extensions when the corresponding CVA6Cfg bits are set.
