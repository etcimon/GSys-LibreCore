Vol II §4.2 — Supervisor Instructions

Canonical: specs/riscv-spec.html#_supervisor_instructions. Source line: specs/riscv-spec.html:78520. Domain: RAM.

The S-mode instructions include SFENCE.VMA for TLB/address-translation cache invalidation, SINVAL.VMA (with Svinval), SFENCE.W.INVAL, and SFENCE.INVAL.IR. SFENCE.VMA is the fundamental coherence mechanism between page-table updates and the address-translation cache: after modifying a PTE, software must execute SFENCE.VMA to guarantee subsequent translations observe the new mapping.

Spec quotation

"In addition to the SRET instruction defined in Section 3.3.2, one new
supervisor-level instruction is provided. The SFENCE.VMA instruction is
used to synchronize updates to in-memory memory-management data
structures with the current execution of instruction fetches, explicit
memory accesses, and page-table walks."
(specs/riscv-spec.html:78520-78525, anchor #_supervisor_instructions)

CVA6 status: implemented. SFENCE.VMA is decoded in core/decoder.sv and executed in core/controller.sv; it flushes the ITLB/DTLB and PTW state in core/cva6_mmu/cva6_mmu.sv. Svinval (SINVAL.VMA, SFENCE.W.INVAL, SFENCE.INVAL.IR) support is gated by CVA6Cfg.RVSINVAL and should be verified per target.

.dts linkage: no dedicated DT node; SFENCE.VMA/Svinval availability is implied by the riscv,isa string and mmu-type and by the TLB/PTW configuration.
