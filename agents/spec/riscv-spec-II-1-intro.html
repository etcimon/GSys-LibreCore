Vol II chapter 1 — Introduction

Canonical anchors: #_risc_v_privileged_software_stack_terminology (1.1), #_privilege_levels (1.2), #_debug_mode (1.3). Source lines: specs/riscv-spec.html:68620 (1.1), :68722 (1.2), :68912 (1.3).

This chapter introduces privileged-architecture terminology (M/S/U modes, privilege stack, debug mode) and the debug-mode CSRs. It sets the context for the machine-mode, supervisor-mode, and hypervisor chapters. Debug mode is a special state entered through an external debug request or an EBREAK in debug-mode configuration.

Spec quotation

"This section describes the terminology we use to describe components of
the wide range of possible privileged software stacks for RISC-V."

"At any time, a RISC-V hardware thread (hart) is running at some
privilege level encoded as a mode in one or more CSRs (control and
status registers). Three RISC-V privilege levels are currently defined."

CVA6 status: partially implemented. The privilege mode is maintained in core/csr_regfile.sv and used for CSR access permission checks. The debug unit is connected at the top level via debug_req_i in core/cva6.sv; debug CSRs (dcsr, dpc, dscratch0/1) are declared in core/include/rvfi_types.svh:44-47 and handled in core/csr_regfile.sv. M/S/U mode context switches, ECALL/EBREAK/MRET/SRET/WFI, and trap entry/return are sequenced in core/controller.sv.

.dts linkage: the CPU node status and riscv,isa indirectly reflect the supported privilege levels; the debug module is declared in the SoC device tree (e.g. riscv,debug-013 node) and tied to debug_req_i.
