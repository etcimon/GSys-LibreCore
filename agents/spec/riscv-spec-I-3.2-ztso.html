Vol I §3.2 — Ztso Extension for Total Store Ordering

Canonical: specs/riscv-spec.html#ext:ztso. Domain: SPEC, CACHE.

Ztso augments RVWMO with the RISC-V Total Store Ordering (RVTSO) model. RVTSO makes the following adjustments to RVWMO: all loads behave as if they have an acquire-RCpc annotation, all stores as if they have a release-RCpc annotation, and all AMOs as if they have both acquire-RCsc and release-RCsc annotations. Vector memory instructions also follow RVTSO at the instruction level. Implementing it requires that all stores become visible to all harts in a total order and that loads see stores in that order unless explicitly allowed otherwise. This impacts the write-buffer drain, store-to-load forwarding, and any cache-coherence protocol.

"RVTSO makes the following adjustments to RVWMO:
  - All load operations behave as if they have an acquire-RCpc annotation.
  - All store operations behave as if they have a release-RCpc annotation.
  - All AMOs behave as if they have both acquire-RCsc and release-RCsc
    annotations.
  - Additionally, if the Ztso extension is implemented, then vector memory
    instructions in the V extension and Zve* family of extensions follow
    RVTSO at the instruction level."
(specs/riscv-spec.html:8774-8811, anchor #ext:ztso / #norm:rvtso_adj_rvwmo)

  input  logic        store_commit_i,

CVA6 status: absent. CVA6 implements RVWMO only. No RVZtso configuration bit, no TSO annotation logic, and no store-buffer/load-forwarding serialization beyond RVWMO exists in the source. Enabling Ztso would require structural changes to core/store_buffer.sv, core/cache_subsystem/wt_dcache_wbuffer.sv, and core/load_unit.sv.
