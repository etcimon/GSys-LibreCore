Vol II §3.5 — Non-Maskable Interrupts

Canonical: specs/riscv-spec.html#nmi. Source line: specs/riscv-spec.html:75904. Domain: SPEC.

NMIs are highest-priority interrupts that cannot be disabled by mstatus.mie. They use a dedicated trap vector and preserve the pre-NMI PC in mnepc. NMIs must be taken precisely and cannot be nested until the handler acknowledges the NMI. Any speculation/flush unit must preserve NMI priority over ordinary interrupts and exceptions.

Spec quotation

"Non-maskable interrupts (NMIs) are only used for hardware error
conditions, and cause an immediate jump to an implementation-defined
NMI vector running in M-mode regardless of the state of a hart's
interrupt enable bits. The mepc register is written with the virtual
address of the instruction that was interrupted, and mcause is set to a
value indicating the source of the NMI."
(specs/riscv-spec.html:75904-75912, anchor #nmi)

Pseudo-SystemVerilog synthesis notes

module nmi_unit (
  input  logic        nmi_i,
  input  priv_lvl_e   priv_i,
  output logic        take_nmi_o,
  output logic [XLEN-1:0] vector_o,
  output logic [XLEN-1:0] mnepc_o
);
  // highest priority; disable further NMIs until handler returns
endmodule

CVA6 status: absent / not separately documented. The standard interrupt path uses corev_apu/rv_plic for maskable interrupts, and exceptions are handled in core/controller.sv. There are no dedicated mnepc/mnstatus/mnvec CSRs in core/csr_regfile.sv and no separate NMI trap vector; an NMI would be delivered as a high-priority external interrupt or handled by the SoC.

.dts linkage: no standard DT node for an NMI inside the hart; an SoC-level NMI is usually wired to the PLIC/CLINT or a custom interrupt controller.
