Vol I §5.2 — Zalrsc Extension for Load-Reserved/Store-Conditional Instructions

Canonical: specs/riscv-spec.html#ext:zalrsc. Domain: SPEC, RAM, CACHE.

LR loads a word/doubleword from the address in rs1, places the sign-extended value in rd, and registers a reservation set: a set of bytes that subsumes the bytes in the addressed word. SC conditionally writes a word in rs2 to the address in rs1; it succeeds only if the reservation is still valid and the reservation set contains the bytes being written. If SC succeeds it writes the word to memory and writes zero to rd; if it fails it does not write to memory and writes a nonzero value to rd. Executing an SC invalidates any reservation held by this hart.

Spec quotation

"LR.W loads a word from the address in rs1, places the sign-extended
value in rd, and registers a reservation set: a set of bytes that
subsumes the bytes in the addressed word. SC.W conditionally writes a
word in rs2 to the address in rs1: the SC.W succeeds only if the
reservation is still valid and the reservation set contains the bytes
being written. If the SC.W succeeds, the instruction writes the word in
rs2 to memory, and it writes zero to rd. If the SC.W fails, the
instruction does not write to memory, and it writes a nonzero value to
rd. ... Regardless of success or failure, executing an SC.W instruction
invalidates any reservation held by this hart."
(specs/riscv-spec.html:14329-14378, anchor #ext:zalrsc / #norm:lr_w_op)

CVA6 status: implemented when CVA6Cfg.RVA is set. Decode in core/decoder.sv:1602-1637 emits AMO_LRW/AMO_SCD etc.; the LSU selects the operation at core/load_store_unit.sv:728-748; core/store_unit.sv:134-135,282-319 converts to AMO_LR/AMO_SC; core/amo_buffer.sv:50-63 holds the AMO until non-speculative commit. The WT cache path implements SC success/fail through the read-modify-write response and an exponential backoff counter in core/cache_subsystem/wt_dcache_missunit.sv:334-347,576-583 and the AXI lock encoding in core/cache_subsystem/wt_axi_adapter.sv:252-267,577-580. The HPDcache path uses an explicit LR/SC reservation snoop in core/cache_subsystem/hpdcache/rtl/src/hpdcache_ctrl.sv:157-161,1179-1181 / hpdcache_uncached.sv:84-89,149-150.

.dts linkage: the reservation-set size is tied to the cache-line width and is only valid on cacheable/coherent memory nodes matching the CachedRegion PMA configuration.
