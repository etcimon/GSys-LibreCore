Vol II §4.4 — Sv39: Page-Based 39-bit Virtual-Memory System

Canonical: specs/riscv-spec.html#sv39 (source line 79453). Domain: RAM. Siblings: #sv32, #sv48, #sv57.

The purpose of §4.4 is to define a simple paged virtual-memory system for SXLEN=64 that supports 39-bit virtual address spaces, chosen because for many systems 39 bits of virtual-address space is ample, trading the larger reach of Sv48/Sv57 against the latency of page-table traversals and the size of hardware structures that store virtual addresses. It is the default translation mode for 64-bit Linux-class RISC-V and the mode most 64-bit CVA6 targets use.

Spec quotation

"This section describes a simple paged virtual-memory system for
SXLEN=64, which supports 39-bit virtual address spaces. The design of
Sv39 follows the overall scheme of Sv32, and this section details only
the differences between the schemes."
...
"We specified multiple virtual memory systems for RV64 to relieve the
tension between providing a large address space and minimizing
address-translation cost. For many systems, 39 bits of virtual-address
space is ample, and so Sv39 suffices."
(specs/riscv-spec.html:79453-79472, anchor #sv39 / #norm:Sv39_sxlen)

Mechanically, Sv39 supports a 39-bit virtual address space divided into 4 KiB pages; effective addresses must have bits 63-39 all equal to bit 38, or else a page-fault exception will occur. Translation maps the 27-bit VPN into a 44-bit PPN via a three-level page table, while the 12-bit page offset is untranslated. Sv39 page tables contain 512 8-byte PTEs, are exactly one page in size, and must be page-aligned; the root page-table PPN comes from satp. CVA6 implements the walker, I/D TLBs, and mode selection in core/cva6_mmu/: the mode enum is core/include/config_pkg.sv:45-52 (ModeSv39 = 8), the satp PPN and translation enables are driven from core/csr_regfile.sv and wired through core/cva6.sv:1074-1096,1208-1226 to the MMU. The page-table walker itself is core/cva6_mmu/cva6_ptw.sv:23- with state machine at :332, PTE validation at :279-294, and misaligned superpage detection at :183-198. Canonicality checks for fetch are in core/cva6_mmu/cva6_mmu.sv:399-401 and for load/store at :538-540,615. The I- and D-TLBs are in core/cva6_mmu/cva6_tlb.sv and the shared TLB in core/cva6_mmu/cva6_shared_tlb.sv. This links to the PMP sub-file (page-table reads are PMP-checked at effective privilege S) and to PMA (translated physical addresses are then PMA-checked).

Pseudo-SystemVerilog synthesis notes

The implied structure is a three-level page-table walker over 8-byte PTEs with a canonicality check, cross-referenced to core/cva6_mmu/:

module sv39_ptw (
  input  logic [38:0] vaddr_i,       // VPN[2:0] = vaddr[38:30],[29:21],[20:12]
  input  logic [43:0] satp_ppn_i,    // core/csr_regfile.sv (satp.PPN)
  // canonicality: vaddr[63:39] must all equal vaddr[38] else page-fault
  output logic [55:0] paddr_o,       // 44-bit PPN : 12-bit offset
  output logic        page_fault_o
);
  // for level in {2,1,0}: pte = mem[ (ppn<<12) + vpn[level]*8 ];
  //   if !pte.V or bad RWX -> page_fault; if leaf -> assemble PA (superpage if level>0);
  //   else ppn = pte.ppn; each pte access is PMP/PMA checked.
endmodule
