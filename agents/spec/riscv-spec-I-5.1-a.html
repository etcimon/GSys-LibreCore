Vol I §5.1 — A Extension for Atomic Instructions

Canonical: specs/riscv-spec.html#ext:a (source line 14288). Domain: SPEC, RAM, CACHE.

The A extension comprises the Zalrsc and Zaamo sub-extensions. Atomic operations to aligned, naturally-sized memory locations must be performed atomically with respect to all harts. The memory-ordering bits (aq/rl) on these instructions directly map to RVWMO dependency/ordering rules. Atomics interact with speculation because a speculatively executed atomic must not modify the reservation or memory state until commit.

Spec quotation

"The A extension comprises the Zalrsc and Zaamo extensions, which are
defined in the following sections."

module atomic_unit (
  input  logic [XLEN-1:0] addr_i, rs2_i,
  input  amo_op_e         op_i,       // LR/SC/AMO with aq/rl
  input  logic            commit_i,   // only act at commit
  output logic [XLEN-1:0] result_o
);
  // reservation table + AMO ALU; ordering bits fed to memory controller
endmodule

CVA6 status: implemented when CVA6Cfg.RVA is set. Decode is in core/decoder.sv:1602-1647 (AMO opcode classification for word/double LR/SC/AMOs). The execute path converts instructions to AMO_LR/AMO_SC/AMO_* in core/store_unit.sv:134-135,282-319, routes them through core/load_store_unit.sv:728-748, and buffers the AMO until commit in core/amo_buffer.sv:50-63. The atomic data path is completed by the cache subsystem: either the WT path (core/cache_subsystem/wt_dcache_missunit.sv:334-347,576-583 and core/cache_subsystem/wt_axi_adapter.sv:252-267,577-580) or the HPDcache path (core/cache_subsystem/cva6_hpdcache_if_adapter.sv:189-219 and core/cache_subsystem/hpdcache/rtl/src/hpdcache.sv). The AMO arithmetic is in core/cache_subsystem/amo_alu.sv:14-65.

.dts linkage: the AMO capability is reported through the ISA string (riscv,isa); CVA6 derives the A letter from CVA6Cfg.RVA. Atomic regions must be in cacheable/coherent memory nodes, matching the CachedRegion PMA rules.
