Vol II §3.1-3.3 — Machine-Level ISA

Canonical anchors: #_machine_level_csrs (3.1), #_machine_mode_privileged_instructions (3.3), #_multi_regional_address_translation_and_protection_catalog_2 (3.3/3.6/3.7). Source lines: specs/riscv-spec.html:71698 (3.1), :75595 (3.3).

This group covers M-mode CSRs (mstatus, misa, mie, mip, mtvec, mscratch, mepc, mcause, mtval, mconfigptr, mvendorid, etc.), M-mode instructions (ECALL/EBREAK/MRET/WFI), and the multi-region address-translation/protection catalog (PMA/PMP). It is the foundation of the privileged architecture and must be implemented before any S-mode or U-mode features.

Spec quotation

"In addition to the machine-level CSRs described in this section,
M-mode code can access all CSRs at lower privilege levels."
...
"The ECALL instruction is used to make a request to the supporting
execution environment. When executed in U-mode, S-mode, or M-mode, it
generates an environment-call-from-U-mode exception. The MRET
instruction is used to return from a trap taken in M-mode."
(specs/riscv-spec.html:71698-71701 anchor #_machine_level_csrs;
:75595-75610 anchor #_machine_mode_privileged_instructions)

CVA6 status: implemented. M-mode CSRs are read/written in core/csr_regfile.sv (e.g. mstatus, misa, mie, mip, mtvec, mepc, mcause, mtval, PMP CSRs). ECALL, EBREAK, MRET, and WFI are decoded in core/decoder.sv and sequenced by core/controller.sv. The multi-region address-translation/protection catalog is implemented by PMA rules in core/include/config_pkg.sv:472-502 and PMP in core/pmp/ (see agents/spec/riscv-spec-II-3.6-pma.html and riscv-spec-II-3.7-pmp.html).

.dts linkage: the CPU node carries riscv,isa and mmu-type derived from misa/mstatus and the paging config; memory@ nodes must align with PMA/PMP regions.
