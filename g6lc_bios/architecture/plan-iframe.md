# BIOS windowing, tabs, and iframe sessions — later plan

**Status:** B92g landing. Window/tab **chrome is Svelte** (`App.svelte` /
fixtures); crate **`g6b-iframe`** is a session pool (`ensure` / `drop` /
navigate), not a window manager. Kernel registers hooks and fulfills
`HostNeed` GETs (local FileServe, `app:files`, gated outbound `http(s):`).
Intern tokens map to a guest object table. Nested `/ui/*.wasm` cells are
still later in B92e. Green remains `python tools/g6b.py check`. QEMU BIOS
argv never `-netdev`.

**Ancestor:** [`plan-endpoint.md`](plan-endpoint.md) (one `BrowserSession`,
one LDC cell, live CSS). This file is the **shell on top of that engine**:
windows, a Firefox-like tab engine, iframe sessions, and virtual-app hooks.

**Not Chromium.** Nested pages are more instances of the same
js / DOM / wasm / `Engine::paint` path, not a second browser process.

---

## 0. Thesis

The BIOS setup UI is the **desktop**. It already owns the banner, setup
tabs, and `#status`. Later it also owns a **windowing system**. A window is
a separate application. A **browser window** has a Firefox-like tab strip.
Each tab is an **iframe session** that can navigate.

The URL in a tab is a string. It may be:

- a **local app path** (`app:files`, `app:ssh`, `/ui/help.html`, …), or
- a **remote URL** (`https://…`).

Local apps are KernelPort + FileServe + a hook that mounts a cell or HTML
into the session. Remote URLs use a **gated outbound GET** that is not
QEMU `-netdev` (kernel fetch → `g6b-http` plan → hw TCP; mailbox after
`NET-DELEGATE`). `kernel.http.outbound` is off by default and **on** for
appliance/desktop/full. Unarmed, a remote location is stored and shown,
and the load **fails closed** with `outbound fetch disabled` — never a
silent blank or a fake page.

Goosie still treats CSS `<iframe>` as out of scope (`display: none`,
unsupported-feature). This plan does **not** implement iframe as a
replaced CSS box. The `<iframe>` node (libwasm `HTMLIFrameElement`) is the
**session controller** (`src` / `srcdoc` / `contentWindow`). The visible
chrome is generated by the BIOS UI.

## 1. What sits on the current structure

| Current | Role in this plan |
|---|---|
| `App.svelte` / LDC cell (`WasmUi`) | **Shell.** Setup menus stay; it also creates windows, tab strips, and writes the BIOS status bar. |

| `KernelPort` / `g6b-http::Router` | **Shell and registered local apps only.** An iframe session does not inherit the BIOS UI’s `holycEval` / `registerEndpoint` / `/bios/*` surface. See §5.1 and §6.3. |
| FileServe `/ui/*` | Local HTML/CSS/wasm pages a tab can navigate to. |

| DedicatedWorker (B58) | Compute inside an app, not a second UI engine. |
| HolyC dual-band / `SshHolyc` | Twin of the SSH **web app**, not a replacement for it. |
| FileMgr / `/bios/files/*` | Twin of the filesystem **web app**. |

HolyC-UI remains a different face (`MENUS.md`). This plan is the browser
face only.

## 2. Layers (shell → window → tab → session)

```
BIOS UI  (App.svelte / one WasmUi)
  ├─ setup chrome (banner, setup tabs, #refresh)
  ├─ #status          ← BIOS status bar (focused tab URL + load state)
  └─ windowing system
       └─ Window (app container, z-order, focus, title, close)
            └─ if kind=browser: Firefox-like tab engine
                 └─ Tab
                      └─ IframeSession
                           location, history, document subtree
                           createBrowserContext
                           optional nested WasmUi
                           navigate(local | remote)
```

**Status bar is BIOS chrome**, not a strip glued to the iframe. `#status`
(or a dedicated `#bios-status` if the setup line must stay) always
reflects the **focused window’s active tab**: location string, load phase
(`idle` / `loading` / `ok` / `error`), HTTP status or hook name.

A window that is not a browser (a dedicated app pinned to `app:files`)
still has one session; the tab strip can hide until there is more than
one tab.

## 3. Windowing system

Generated by the Svelte shell, not by the kernel. `FrameEngine` does not
open windows or select tabs; Svelte `{#if winOpen}` / tab chips call
`ensure` / `drop` / `navigate` on a slot.

Each window:

- `id`, `title`, `kind` (`browser` | `app`)
- `position:absolute` with **explicit** `width`/`height` (g6b-css refuses
  shrink-to-fit on absolute boxes)
- z-order integer; click focuses; close removes the node and drops sessions
- title bar (title + close). Drag/resize are a later increment.
- a **stage** node (`#win-N-stage`) where the active tab’s document hangs

Budgets (fail closed): `MAX_WINDOWS = 4`, `MAX_TABS_PER_WINDOW = 8`,
`MAX_SESSIONS = 8`. Opening past the budget is a status-bar error, not a
silent drop of another window.

The shell’s setup page is **not** a window. It stays the desktop. Windows
stack above it (absolute, later in paint order).

## 4. Firefox-like tab engine

Only inside `kind=browser` windows (the “web app” that hosts iframe
sessions).

| Control | Behaviour |
|---|---|
| Tab strip | One chip per tab; active tab `bios-tab-active` (same class as setup). |
| New tab | Empty session at `about:blank`; focus location. |
| Click tab | Swap which session’s document is the stage’s child (`hidden` on the others, or reparent). |
| Close tab | Drop that session’s context + nested `WasmUi`. Last tab closes the window. |
| Navigate | Set `session.location`, push history, run the loader for that URL. |

History is a bounded stack per session (`MAX_HISTORY = 32`): back/forward
are later; v1 may only replace. Title comes from `<title>` or the hook’s
label.

This is **not** the setup-menu tab strip. Setup tabs remain BoardSpec
menus. Browser tabs are iframe sessions.

## 5. Iframe session

One session is one nested browsing instance:

```
IframeSession {
  id, context_id,           // createBrowserContext — never the shell's
  location: Url,            // what the URL bar / status bar show
  history: [Url],
  document: Node,           // subtree under the stage when active
  wasm_ui: Option<WasmUi>,  // if this page is a libwasm cell (own instance)
  timers: TimerHeap,        // own heap; ids do not alias the shell's
  caps: CapSet,             // default deny native (HolyC / KernelPort)
  store: Option<{ uuid, purpose, drop_on_close }>, // bios.store bind; see g6b-store-instances.md §7
  load: Idle | Loading | Ok | Error(String),
}
```

`HTMLIFrameElement.src` / `srcdoc` on a controller node in the shell (or
in an app) **open or navigate** a session. `contentWindow` is the nested
context’s interned `window` handle (B72 isolation). `contentDocument` is
the nested document handle. Cross-session DOM reads stay forbidden.

Svelte may pass a parent JS map as the `vars` attribute (`vars={frameVars}`
or a JSON object). Allowed keys are interned into the nested JS environment
(`window.greeting`, `ctx.global("greeting")`) on every re-populate,
including a remote location whose fetch is still fail-closed. Reserved
names (`eval`, `holycEval`, `pglite`, `window`, …) are refused. Functions
stay host callables; they are not KernelPort.

`about:blank` is an empty document with its own `window`/`document`.
`srcdoc` parses the attribute string and skips fetch.

Pointer hits inside the stage dispatch into that session’s tree (remap
hit paths like B88). Hit-id lookup is **scoped to `session.document`**,
never `each_id` across the shell (duplicate `#tab-cpu` must not restyle
setup chrome). The shell still receives title-bar and tab-strip clicks.

### 5.1 Fresh JS environment — no mix with the BIOS UI

A new session (new tab, navigate, or close then open) **re-populates**
the JS environment. It does not clone, share, or intern the shell’s.

| What | Per iframe session | Must not be |
|---|---|---|
| `createBrowserContext({ contextId })` | new `window` / `document` / console ring | the shell context (`contextId=main`) |
| Object table + handles 1/2 | this context’s `document`/`window` | the shell `WasmUi` table |
| `window.__svelteD.ts` / `JsExports` | empty, or that page’s own exports | `App_svelte.fetchBios` / `holycEval` / `registerEndpoint` |
| Nested `WasmUi` | own module + memory + tables | the shell cell |
| `TimerHeap` | own ids from 1 | the UI-hart heap used by setup tabs |
| `KernelHost` / `Host` | bound to `session.document` | `&mut BrowserSession.dom` |
| `getRoot()` | the session stage mount | `#libwasm-root` / `#libwasm-spa` |

**Re-populate** means: drop the previous context + nested instance +
timers + interned Event objects, then construct a new context and (if
the loader says so) a new cell. Navigate is not “swap `location` and
keep `window`”. `about:blank` after a `/ui/…` page is a new empty
document, not a reused heap with leftover globals.

The shell `WasmUi` is the **desktop**. An iframe session is a **guest
of that desktop**. Same engine (js / DOM / wasm / `Engine::paint`),
different instance. One raster of the shell tree is allowed only if
the session’s nodes hang under the stage **and** no host import on the
iframe can name a shell node.

HolyC **bindings** (the `env.holyc` import, `JsExportKind::HolycEval`,
`KernelPort::holyc`, `registerEndpoint`) live on the **shell host** and
on a **registered local app** that declared them. They are not copied
into a new iframe session’s import table. A nested cell that imports
`env.holyc` without the cap is a **verifier reject**, not a no-op that
returns 0 (id-0-style holes are refused).

## 6. The URL (local app path or remote)

The location is a string. Parse it, then **dispatch**. Never guess.

### 6.1 Local app path

| Location | Meaning | Loader |
|---|---|---|
| `about:blank` | empty session | no fetch |
| `/ui/…` `.html`/`.css`/`.wasm` | FileServe page | `KernelPort` GET; HTML parse; optional nested cell |
| `app:files` / `/apps/files` | filesystem virtual app | hook mounts FileMgr cell / HTML |
| `app:ssh` / `/apps/ssh` | SSH+HolyC web app | hook mounts a terminal cell; I/O is HolyC dual-band / mailbox, **not** a netdev |
| `app:setup` / `/apps/setup` | the setup tree as an app (optional) | already the desktop; may refuse as a nested copy |
| `/bios/www` | listing of mounted UI files | JSON → a small directory page, or navigate from there |

`/bios/menu/cpu` is **fetch JSON**, not a webpage. A tab whose location is
a JSON endpoint fails closed unless a hook claims that prefix.

Local `src` today is images only (`/ui/*.svg|png|jpg|ico`). This plan
extends the allow-list to **local documents** (`/ui/*.html`, `/ui/*.wasm`
when the ABI verifier accepts the cell) and to **registered app paths**.
`javascript:` and `file:` stay refused. USB FileMgr does not become
`file://`.

### 6.2 Remote URL

`http:` and `https:` are valid location strings. Loading them is a
**gated outbound fetch**, not QEMU `-netdev`.

```
https://example/path
        │
        ▼
  BoardSpec kernel.http.outbound  (off by default; appliance/desktop/full arm it)
        │
        ├─ unarmed → session.Error("outbound fetch disabled"); status bar shows the URL + error
        │
        └─ armed:
             pre-NET-DELEGATE: **kernel** GET (`kernel_fetch` / iframe `HostNeed::RemoteHtml`)
                               `g6b-http::plan` → hw TCP (`via=hw-tcp`)
                               HTTP/1.1 GET on the socket; HTTPS is `g6b-tls` ClientHello
                               on the same socket (fingerprint, not an HTML body; B54)
                               still no QEMU -netdev; iframe guests never KernelPort / HolyC
             post-NET-DELEGATE: GET via /dev/g6lc-bios mailbox
                               Linux owns eth/wifi; BIOS does not grow a NIC
        │
        ▼
  body → HTML parse into the session document (same g6b-html / Engine::paint)
  scripts → same fail-closed interpreter / nested cell verifier
  images → only if they resolve to an allowed URL (local /ui or same outbound gate)
```

Kernel `HttpGet` / `HttpsGet` is the same lowering ([`TLS.md`](TLS.md),
[`g6b-hw.md`](g6b-hw.md)). The HTTPS fingerprint is **not** an HTML body.
This plan does not add Chromium net, libcurl, or OpenSSL, and does not
put HTTPS inside `g6b-hw`.

Remote **wasm cells** are refused in v1 (ABI + supply chain). Remote
pages are HTML+CSS+the existing JS subset. Unimplemented APIs fail closed.

The native `kernel.ts` host (a real desktop browser loading `/ui/`) may
use the host’s `fetch` for remote URLs when outbound is armed **for that
host**. That is the second host of the same ABI ([`plan-endpoint.md`](plan-endpoint.md)
§9), not evidence that QEMU has a NIC.

### 6.3 Native access (fail closed unless local)

**Native** here means kernel I/O the BIOS UI itself uses: `env.holyc` /
`holycEval`, `registerEndpoint`, `/bios/*` (menus, files, display,
settings), USB FileMgr mutation, dual-band UART, mailbox, anything that
is not “fetch this document and its `/ui` assets”.

| Origin | JS environment | Native KernelPort / HolyC |
|---|---|---|
| Shell (BIOS UI, not an iframe) | one privileged `WasmUi` | **yes** — this is the desktop |
| Registered local app (`app:files`, `app:ssh`, BoardSpec hook) | new session | **only the hook’s declared I/O** (files GET, SSH dual-band, …). Not a general HolyC REPL unless the hook names it |
| Local path `/ui/*.html`, `srcdoc`, `about:blank` | new session | **no.** FileServe GET of that document + same-prefix `/ui` assets. No `holyc`, no `/bios/menu`, no `registerEndpoint` |
| Local path `/ui/*.wasm` | new nested `WasmUi` | **no** by default. ABI verifier must reject `env.holyc` / `register_endpoint` unless this path is also a registered app or a later elevation grant exists |
| Remote `http(s):` | new session, HTML+CSS+JS subset | **never.** No elevation to HolyC. Outbound fetch is not KernelPort |

Store instances ([`g6b-store-instances.md`](g6b-store-instances.md)):
`bios.store` is native like FileMgr. A registered app may declare
**purposes** (e.g. `files`). The shell may bind
`session.store = {uuid, purpose, drop_on_close}` — new iframe apps default
to a **deletable Memory** instance (`drop_on_close=true`); USB import binds
an existing uuid with `drop_on_close=false`. Remote sessions never get a
store. The session uuid is not interned into a nested `window.pglite`
unless the hook declared the cap.

`javascript:`, `file:`, `data:` documents stay refused. Remote wasm
cells stay refused in v1. A custom `/ui/myapp.wasm` does **not** get
`KernelPort + registerEndpoint` just because it loaded; that line in §7
is the **registered-app** case, not every local cell.

The fetch allow-list is **per cap**, not `setup_reads` of the setup
page. Reusing `RouterPort` as-is on an iframe would let a tab
`GET /bios/menu/cpu` and paint the BIOS tree — that is mixing, and it
is refused.

### 6.4 Later: HolyC-derived elevation (BIOS chrome prompt)

Local **paths** (not already a registered app) may later **request**
native access. Remote origins cannot. The request is not a JS
`confirm()` inside the iframe (the page must not spoof the prompt).

```
iframe JS / cell
    │  request("holycEval" | "bios.files" | "registerEndpoint" | …)
    ▼
HolyC capability catalog   ← names, not invented in JS
    │  ElevateAsk(cap, origin, persistence?)
    ▼
BIOS UI chrome (shell)     ← modal over the window, not in the stage
    │  operator Approve / Deny
    ▼
HolyC grant store          ← persistence chosen at approve time
    │
    └─ host re-binds that session's KernelPort / import table
```

**HolyC is the authority.** The catalog, the ask, and the grant live
next to `RegisterEndpoint` / the REPL, not in `g6b-js`. The BIOS UI
only **displays** the prompt and writes the operator’s answer back
through the same kernel port the setup page already uses.

Persistence is **undetermined** at implement time; the plan records
the variants so a grant cannot silently become “forever”:

| Persistence | Meaning | Default if the prompt does not say |
|---|---|---|
| `once` / this function use | one KernelPort call, then drop | **this**, if unspecified |
| `page` / this document | until navigate or `about:blank` | — |
| `session` / this tab | until the tab or window closes | — |
| `origin` | this local path / `app:` prefix until reboot | — |
| `persistent` | BoardSpec / NVRAM / HolyC stored grant across boots | **off** until a later spec names the store |

Deny is the default. Closing the tab drops `page`/`session` grants.
Navigate re-populates JS (§5.1) and drops `once`/`page` grants.
`persistent` must be an explicit operator choice, never the fallback.

v1 of B92 (a–h) **does not implement the prompt**. v1 is fail-closed:
no native on local paths or remote. Elevation is a later stage (B92i)
after the session isolation in B92e is real.

### 6.5 Status bar

Whatever the location is, the BIOS status bar shows it:

```
UI-BOOT  win:browser  tab:2  https://example/path  loading
UI-BOOT  win:browser  tab:2  https://example/path  error: outbound fetch disabled
UI-BOOT  win:files    tab:1  app:files             ok
UI-BOOT  win:browser  tab:1  /ui/help.html         200
```

The window’s title bar can repeat a short title; the **authoritative URL
is in BIOS chrome**.

## 7. Virtual-app hooks

A hook is how a **virtual app** becomes a navigable location without
SvelteKit routing.

```
AppHook {
  prefix: "app:files" | "app:ssh" | "/apps/" | …
  title:  "Files" | "SSH"
  open(session, url)     // mount DOM / nested WasmUi into session.document
  navigate(session, url) // same session, new path (optional)
  close(session)
}
```

Register at BoardSpec / shell init. `registerEndpoint` stays HTTP. A hook
is **not** an HTTP route; it is a factory that fills an iframe session.

Worked examples (later implementations, not this pass):

| App | Location | What mounts | I/O |
|---|---|---|---|
| Filesystem | `app:files` | FileMgr cell (today a setup utility) | `GET /bios/files/{fat32,ntfs,ext4}`; optional `bios.store` purpose `files` (UUID instance, deletable memory, USB import/export) |
| SSH shell | `app:ssh` | a terminal svelte-d cell | `holycEval` / dual-band UART / mailbox `SshHolyc`; never `-netdev`; optional store purpose `ssh` |
| Help / docs | `/ui/help.html` | static HTML | FileServe |
| Custom | `/ui/myapp.wasm` as a **registered** app | nested `WasmUi` | only the hook’s declared KernelPort; otherwise no native until B92i elevation |

The shell handles virtual apps **through the same engine**: js exports,
live DOM, wasm instance, `Engine::paint`. There is no second compositor
and no guest `start_ops` growth.

An app that needs background compute uses the existing DedicatedWorker
protocol (B58), not a hidden iframe.

## 8. Instances and paint

```
1 × shell WasmUi          (App.svelte — windows, tabs, status)
N × IframeSession         (createBrowserContext + document subtree)
0..N × nested WasmUi      (only if that tab loaded a local cell)
1 × Engine                (paint the shell tree, including visible stages)
```

Inactive tabs stay in memory but `hidden` (CSS `display:none` already
skips paint). Skip-if-clean (B88) still applies: mutating the focused
session dirties that subtree.

Nested `getRoot()` for a cell loaded into a tab is the session’s stage
mount, not `#libwasm-root` of the shell (same host-import story as B86,
a new mount path).

Do not blit a second Canvas32 into the iframe until a hook proves the
nested tree cannot live in the shell DOM. Prefer **one tree, one paint**.

## 12. Key decisions

1. **The BIOS UI is the window manager and the status bar.** Apps do not
   draw OS chrome.
2. **A window is an application.** A browser window is the app that holds
   the tab engine.
3. **A tab is an iframe session** (instance + document + location), not a
   setup-menu tab.
4. **The URL is a string that may be local or remote.** Dispatch on
   scheme/prefix; fail closed on unknown.
5. **Remote does not mean a NIC in QEMU.** Outbound is adapter
   `HttpsGet` or post-delegate mailbox.
6. **Virtual apps are hooks into the same engine**, not a second runtime.
7. **One live tree, one `Engine::paint`.** Nested cells mutate a mount
   under the stage.
8. **This is later than B89–B91.** Timers, dirty-tile present, and guest
   instance stay the endpoint order.
9. **A new iframe session re-populates JS.** New context, document,
   handles, timers, optional cell. Navigate drops the old instance. The
   BIOS UI cell is not that instance.
10. **HolyC bindings are not ambient in iframes.** Shell and registered
    local apps only. Local paths have no native until B92i elevation.
    Remote never.
11. **Elevation is HolyC-derived and shown in BIOS chrome.** The page
