# LDC 1.36.0 as the only supported compiler

## How it works

`source/libwasm/spa.d` asserts `__VERSION__ == 2106`. That is DMD frontend **2.106.x**, which is **LDC 1.36.0** (changelog: frontend 2.106.1, LLVM 17.0.6). `druntime-wasm/dub.sdl` sets `version "1.36.0"` as a package version, not as a D `version` identifier — it documents the same pin.

BUILDING.md (`BUILDING.md`) is the process of record:

1. Use LDC ≥ 1.35.0 (the tree itself tightens this to **exactly** 1.36.0).
2. Edit `ldc2.conf` so the `"^wasm(32|64)-"` section sets `post-switches = [ ];`. Without that, the `default` section’s `-I%%ldcbinarypath%%/../import` is inherited and LDC’s stock `object.d` / Phobos shadow `druntime-wasm`.
3. Use a dub new enough to understand `targetArch` / the 2024-01 wasm work (BUILDING: “dub compiled from ~master after 2024-01-10”). LDC 1.36.0 shipped 2024-01-06; its bundled dub may be slightly earlier — observe, do not assume.
4. `dub build --arch=wasm32-unknown-wasi` (optionally `--compiler=ldc2`).
5. `.await` requires Binaryen `wasm-opt --asyncify` (BUILDING’s “asincify” is a typo).
6. `-Oz` is the size-opt lever, commented out in the example `dub.sdl`s.

Stock LDC 1.36 WASM (`etc/ldc2.conf`) already sets `-defaultlib=` and empty `lib-dirs`. That **unhooks link libraries**. It does **not** unhook **imports**. The missing piece BUILDING insists on is clearing `post-switches` so `-I` to LDC’s `import/core`, `import/std`, `import/object.d` disappears. After that, the only `object` module is `druntime-wasm/object.d`, which `static assert`s `CRuntime_LIBWASM` (set by libwasm’s `versions "CRuntime_LIBWASM"`).

LDC 1.36’s own WASM test (`tests/codegen/wasi.d` at tag `v1.36.0`) expects `version(WASI)` and `version(CRuntime_WASI)`, TLS as `__gshared`, and a `__minfo` ModuleInfo section. libwasm **rejects** that contract: it sets `CRuntime_LIBWASM`, compiles with `-fno-moduleinfo`, and does not implement `__minfo`. The two WASM stories are mutually exclusive on one `ldc2.conf`.

`BUILDING.md`

## Invariants

- Do not “upgrade” this tree to LDC 1.42/1.43 without rewriting `druntime-wasm` against that frontend. Construction.
- Do not mix stock `CRuntime_WASI` imports with `CRuntime_LIBWASM` in one compile. Construction.

## Extension points

A future LDC pin belongs in `spa.d`, `druntime-wasm/dub.sdl`, and a new BUILDING paragraph together.

## Open questions

Whether LDC 1.36’s bundled dub satisfies BUILDING’s “after 2024-01-10” rule is observed at first `dub build`.
