The normative CSR constraint is explicit in `specs/riscv-spec.html:9085-9090`: “All CSR instructions atomically read-modify-write a single CSR,” selected by the instruction's twelve-bit CSR field. Splitting address lookup, read, write, and retirement is permitted only if those events still belong to that instruction and preserve its architectural order. A response-valid bit for ordinary CSR reads is not automatically a completion signal for WFI or privilege return.

Finding F1 is a circular CSR address dependency in the active OoO path. `csr_buffer.sv:161-179` selects and registers the address only when `csr_commit_i` is asserted. `ex_stage.sv:607-624` connects that signal to the commit input; `g6lc_core.sv:3096-3097,3270` connects it to `commit_stage.commit_csr_o`. That output is qualified by the successful decision at `commit_stage.sv:264-271,379-390`. However, the decision waits for the CSR read response at lines 331-337, and `csr_decode` captures the address before that decision. Initially the address register is zero. A normal first CSR request can therefore read address zero, reach the illegal-address default at `csr_regfile.sv:1762`, and never produce the commit needed to fetch the correct address. The reference `core/csr_buffer.sv:135-142` selects the matching table entry independently of commit. The discriminator is the tuple `{head_tid, lookup_hit, lookup_addr, req_addr, response_valid, exception, commit_fire}` for the first CSR; observing a correct pre-commit lookup would reject this particular mechanism for that source.

Finding F2 is a separate completion mismatch for system operations. `csr_decode.sv` includes MRET, SRET, DRET, and WFI in `is_req`, but excludes them from `is_rd_req`. `csr_read.sv` drives `rdata_valid_o = req_rd_valid_i`. `commit_stage.sv:331-337` waits for that read-valid signal for every instruction classified as `CSR`. Thus a valid system operation has no completion indication under the same handshake, even though `csr_read` can already assert the return control or the CSR state machine can enter WFI. The correction must define request completion for all CSR-class operations, with read data meaningful only for operations that produce it. Merely forcing read-valid high would lose the distinction between a matched response and no response.

Finding F3 is an event-phase mismatch between retirement and wakeup. `commit_stage.sv:199-225` makes `commit_ack_o[p]` the registered previous-cycle `fire[p]`, while architectural register writes occur in the decision cycle and are suppressed in the acknowledgement cycle. `g6lc_ooo_dispatch.sv:355-388` still computes the commit mirror wakeup as `commit_arch[c] && commit_we_i[c]`, with `commit_arch` derived from that delayed acknowledgement. For an isolated successful CSR or AMO retirement, the decision cycle has write-enable but no acknowledgement; the next cycle has acknowledgement but no write-enable. The physical data mirror at lines 954-958 can write the value, yet the corresponding ready/wakeup event never occurs. Raw execution writeback is intentionally excluded for `tid_late_result_q`, so this is not repaired by the ordinary WB lane. A dependent instruction can remain unready after the correct value is stored. The discriminator is one late-result producer followed by a dependent consumer, recording both PRF write and ready-bit transition.

The same delayed-ack design creates an SMT identity obligation. `sb_commit_bundle` is currently a combinational presentation, despite its name and some historical comments. Mixed-SMT port selection can change with a newly committable privileged head. `sb_lifecycle` frees `commit_sel_slot_i` and the shadow ROB receives the current `commit_instr_i.trans_id`, whereas the acknowledgement represents a prior decision. Delaying only the acknowledgement does not preserve the selected instruction. The repair must carry the selected identity and every associated effect through the delayed interval, or use a common retirement event at all consumers. Pinning the bit without the record is insufficient.

Finding F4 is loss of operand-address ownership under issue backpressure. `g6lc_ooo_dispatch.sv:871-915` retains `iss_sbe_q` while the consumer does not acknowledge it. Lines 941-945 drive each integer PRF address from `iqi_take`, otherwise zero. `g6lc_prf.sv:62-75` captures those addresses unconditionally on every edge. The next stalled cycle can therefore pair the retained instruction with register-zero data. The FP PRF has three shared read ports and analogous take-qualified addresses, so a held FP instruction also needs ownership of its response when another lane becomes active. This is a payload-stability defect at the module interface. The discriminator is a nonzero operand, one accepted candidate, at least two cycles of downstream backpressure, no matching WB bypass, then acceptance.

Finding F5 is an unreserved speculative-store insertion slot. `stb_insert.sv:74-109` captures `lowest_set(~spec_valid_i)` for an accepted store. `store_buffer.sv:450-478` supplies only registered queue validity, not the previous S1 reservation. If the queue is empty, store A captures slot zero; on the next edge store B can also capture slot zero while A is only now entering the queue. B subsequently overwrites A. This is reachable at the store-unit boundary: `store_unit.sv:393-424` permits consecutive `VALID_STORE` cycles with a translated next request. `ready_o` based on queue count does not identify the reserved slot. The correction needs a reservation bitmap covering every accepted insertion not yet reflected in queue state, with exactly-once release on install or cancellation. Its age relationships must also include pending insertions.

Finding F6 is a forwarding snapshot without a payload-lifetime guarantee. `stb_fwd.sv` captures candidate masks, age order, and indices in F1/F2, but its F3 gather reads live `spec_entries_i` and `cmt_entries_i`. The header assumes payloads remain for at least two cycles after a slot is freed. The queue update in `store_buffer.sv:378-414` permits a new insertion to replace a freed payload, and no corresponding two-cycle reclamation protection is established at that interface. Stationary placement while an entry is live does not imply immutability after reuse. Either snapshot the candidate data with F1, or retain/revalidate a generation-tagged source until F3. This review selects snapshotting as the correctness-first implementation direction, followed by banking to contain its register and mux cost.

The speculative-to-committed transfer also needs a complete visibility audit. `stb_commit` captures the popped store in `pend_entry_q` for one cycle, and `store_buffer` includes `commit_pend_v` in drain/empty decisions. However, the F1 forwarding inputs at `store_buffer.sv:722-743` include the speculative queue, committed queue, live incoming store, and S1 insertion; they do not include the committed pending record. The address checker at lines 595-665 similarly has no explicit committed-pending term. A previous sticky match can protect some executions, but it does not establish visibility for a newly arriving load in that gap. The implementation must make this record visible to both hazards and forwarding, or prove and enforce an admission interlock for the whole gap.

Finding F7 is an exact width failure in the latency contract. `g6lc_iq_bank.sv:200-211` sets `FP_LAT=10` but returns a three-bit `wake_cnt` containing `cy-2`; ten minus two is eight, which truncates to zero. Lines 257-274 produce an FP completion offset of `6 + wake_cy(lat)`, or sixteen for that class. `g6lc_iq_arb.sv:372-390` uses a sixteen-bit reservation window and shifts a one into that offset; bit sixteen does not exist, so the reservation mask is zero. These are arithmetic facts, not timing-estimator artifacts. Moreover, `fpu_wrap.sv:79-85` configures different FMA, non-compute, and conversion latencies; one fixed class is not an exact shared-completion schedule. Countdown widths and reservation depth must derive from the maximum supported latency, and each operation class must have an exact publication contract. Variable-latency completion needs retained output capacity.

Finding F8 is that replay cannot restore work after its owner has already disappeared. `g6lc_iq_bank` re-arms speculative ready bits, but its `issued` state is preserved by replay and its entries are released on acknowledgement into dispatch. `g6lc_ooo_dispatch` then owns a separate staged issue record. A later load replay broadcast does not by itself recover a dependent already removed from the IQ, issued to an FU, or written back. The claim in the older analysis that bank-wide re-arm is always conservative is therefore conditional on the dependent still being in a recoverable owner. The design must either prevent uncertain load dependents from leaving that domain or carry speculation lineage into issue/FU/WB state and squash/reissue the complete affected set. The initial boot repair should retain wake-on-real-WB for variable-latency loads until that recovery contract is implemented and checked.

Finding F9 concerns recovery and acceptance at the new dispatch stage. `issue_valid_o` is masked by `flush_i` and `flush_unissued_i`, but `iqi_take` is not masked by those signals; the sequential capture gives flush precedence over acceptance. An upstream acknowledgement can therefore coincide with discarding the corresponding record. In addition, an older instruction already accepted from the IQ must not disappear merely because a younger branch requests an unissued-instruction flush. The cancellation tuple must distinguish front-end unallocated work, accepted surviving work, and architecturally cancelled work. The relevant current-source invariant is acceptance equals durable capture or legitimate cancellation, not simply that the queue is empty after a redirect.

Finding F10 concerns configurability rather than the current RV64/32-slot specialization. The literal-false scalar branch in `id_stage.sv` removes the fallback implementation. `rp_mask_q[31:0]` and the five-bit encoder ignore replay entries above 31 and are out of range below 32. `store_buffer.sv:419-433` counts exactly eight speculative slots. `g6lc_prf.sv:84-103` writes fixed `[63:32]` and `[31:0]` slices despite a `DATA_WIDTH` parameter. The RVH write replacement rejects supported H CSRs if RVH is enabled. These may leave the present specialization unchanged, but they cannot support the requested scalar/n-issue/RVH configuration envelope. Use width-derived constant-index trees and real generate guards; repair the analyzer's specialization facts when folding fails. Do not change functional reachability to improve a report.

The implementation order is an aggregate sequence of related contracts. Batch A restores the retirement and CSR transaction boundary across `commit_stage`, `sb_commit_bundle`, `sb_lifecycle`, `scoreboard`, `issue_stage`, `g6lc_ooo_dispatch`, `g6lc_core`, `csr_buffer`, `csr_decode`, `csr_read`, `csr_regfile`, `csr_trap`, `csr_write`, counters, RVFI, and the SMT PC/context consumers. Define one architectural retirement event containing `{valid, tid, generation, hart, instruction, drop, exception, destination class, physical destination, write enables, final write data}`. Architectural maps, PRF mirror wakeup, CSR effects, RVFI, and instret consume that event. If reclamation remains delayed, it receives a separate captured identity; it must never infer the old event from a newly selected live head. Removing the present alternating decision/ack bubble is a throughput objective of this batch, not an independent acknowledgement optimization.

Batch A's CSR seam separates `lookup_valid/lookup_tid` from `release_valid/release_tid`. A lookup can complete before retirement and must return a matching address and identity. The request record then carries address, operation, operand, privilege/virtualization context, and identity; its response carries completion, optional read value, exception, and identity. A held response remains valid until consumed or cancelled. CSR writes and xRET/WFI effects are applied only when the serialized architectural event is authorized. Use an explicit accepted-request state rather than suppressing repeated field values: equal fields do not prove that two requests are the same allocation generation. Return completion for non-reading system operations. Preserve exception, interrupt, debug, PMP, SATP, FP-dirty, and counter priority from the reference writer.

Batch B repairs issue ownership and capacity as one change across `g6lc_rename*`, `g6lc_iq*`, `g6lc_ooo_dispatch`, `g6lc_prf`, and `issue_read_operands`. The selected instruction, source tags, available operands, speculative-source identities, and completion-resource reservation form one held packet. Capture read responses per issue lane before shared FP read ports are reused; retain the packet under downstream stall. Acknowledgement requires durable capture. A global flush removes all speculative packets; a branch recovery removes only its architectural younger set, including accepted packets outside the IQ. Rename reservations remain charged from pick through publish or cancellation, and readiness is refreshed from WB events that occur while a group is staged. The present `grp_pend_q` serialization must be recorded honestly: R1/R2/R3 registers alone do not provide one group per cycle.

Batch B also replaces fixed three-bit countdowns and sixteen-slot windows with common derived widths. Let `Lmax` be the largest supported fixed producer publication distance, `K` the actual accepted-grant-to-FU-input distance, and `Omax` the maximum completion offset. Countdown storage must represent its largest initialized value without truncation; the reservation vector must have at least `Omax+1` bits. Use a shared package function for ALU-low, ALU-full, branch, multiply, each fixed FP group, and any other fixed producer. Assert representability at elaboration and schedule correspondence at the producer boundary. A ready signal sampled several cycles earlier is not a reserved credit for a variable-capacity FU. Keep such operations owned in an elastic path and reserve their completion storage on actual acceptance.

Batch C repairs the memory ownership sequence across `load_store_unit`, `lsu_bypass`, `store_unit`, `stb_insert`, `store_buffer`, `stb_commit`, `stb_drain`, `stb_fwd`, `g6lc_lsq_event/slot/cam_bank/age/reduce/verdict/release`, and `load_unit`. Every accepted store reserves a distinct speculative slot immediately. Both pending insertion and committed-pending records participate in forwarding and hazard views. F1 snapshots the candidate byte data, byte enables, zero-block metadata, and ordering identity with the match; F2 selects; F3 publishes from that same snapshot. No source may change identity between matching and gather. Committed stores survive flush; speculative cancellation and load tombstones remain different lifetime rules.

For Batch C, `ld_checked` must mean all prior relevant verdict work has been incorporated, not merely that an address arrived or a dependency mask became empty. A store-address event can clear an unresolved mask before its delayed violation tournament reaches the verdict stage. Track pending validation obligations through that interval and require the load's generation to match at publication. On simultaneous clear/set/reuse, old-generation results cannot set the new generation's checked bit. A `wait` verdict, a memory-order violation, and a cache miss are different events; merge them without losing distinct owners. Returning data is retained until forward resolution and final permission/order checks complete. Exceptions must remain deliverable without requiring data-path completion that a faulting access cannot produce.

Batch D restructures the ALU, branch, multiplier, and completion fabric across `alu`, `alu_shift_hi`, `alu_wrapper`, `branch_unit`, `multiplier`, `mult`, `serdiv`, `aes`, `fpu_wrap`, `ex_stage`, the IQ latency descriptors, and WB consumers. Split by real function and representation: predecode/select; bounded add/logic; staged shift/compare; partial-product generation; carry-save reduction; final carry propagation; result publication. Preserve all parallel alternatives, including CLMUL, MULH variants, MULW extension, flags, valid, TID, generation, and cancellation. A file boundary is hierarchy only; a register carrying the complete operation creates the timing boundary.

The multiplier candidate uses a generated reduction schedule with a bounded number of compressor levels per stage and parameterized final-adder chunks. The current three-level stages read 16.2 structural FO4; a one-level stage is a candidate to measure, not a proven 5.4-FO4 implementation once routing and stage control are included. The 64-bit high-half carry-propagate operation in S7 must also be partitioned or changed to a bounded prefix/carry-select representation. `MultStages` is derived from the implemented schedule and propagated to `mult` ownership, IQ wakeup, and completion reservations in the same batch. Increasing the parameter without changing the selected implementation is prohibited: the legacy `MSTAGES > 3` arm currently implements a particular staged form, not arbitrary depth.

The ALU candidate preserves partial-value forwarding only for consumers whose first-stage computation needs the available portion. A producer's low-half-ready flag alone does not establish that a branch compare, address generation, shift amount, or full-width operation can consume it. Record availability per operand portion, qualify it with the producer generation, and align the late high half with the same consumer. The completion fabric should use retained per-unit result records and explicit sink acceptance; its current priority mux relies on collision-free arrival, so a wrongly predicted offset can silently discard a result. A small output queue per contested lane can preserve results, but its depth and credit policy must account for the maximum accepted work and cannot be justified by OoO alone.

Batch E restructures the WT write-buffer transaction state across `wt_dcache_wbuffer`, its existing helper modules, `wt_dcache_mem`, `wt_dcache_ctrl`, `wt_dcache_missunit`, `wt_cache_subsystem`, `wt_axi_adapter`, and `store_buffer`. Separate admission/reservation, byte coalescing, transaction dispatch, return/fixup, and invalidation. Use per-entry state with explicit versioned pending writes, rather than composing dynamic return selection, allocation, supersession, and byte clearing into one broad next-state path. Accepted pending records remain visible to cache byte forwarding, conflict detection, empty/drain status, and fences until installed. Batch F covers fetch and decode callers: `frontend`, `g6lc_fe_nextline`, `g6lc_fe_btb_check`, `g6lc_fe_override`, `g6lc_fe_redirect`, `g6lc_ftq`, `g6lc_fdip`, `g6lc_loop_buffer`, `g6lc_bp_*`, `ras`, `g6lc_icache`, `instr_realign`, `instr_scan`, `instr_queue`, `id_stage`, `g6lc_decode_s1/s2/s3`, compressed/macro/Zcmt decoders, and scoreboard admission. Trace a fetch as `{hart, window address, token, epoch}` and an instruction as `{hart, PC, instruction bytes, allocation generation}`. Check hit, miss, refill after kill, FENCE.I, RVC straddle, partial packet acceptance, replay, override, predictor checkpoint restore, and concurrent architectural redirect. Preserve legal scalar branches. Override training and architectural misprediction are distinct events, and token wrap requires a bound on still-owned requests.

Batch G covers translation, privilege, and system integration: `g6lc_mmu`, `g6lc_tlb`, `g6lc_shared_tlb`, `g6lc_ptw`, PMP entry/decision modules, LSU translation clients, CSR context, `g6lc_hart`, cluster/SoC wrappers, AXI CDC and bridges, boot ROM, CLINT, PLIC, timer, UART, and debug. Each translation response carries the requesting access's hart, privilege, ASID/VMID, address, access type, and epoch; a late PTW exception must not be attached to a newer DTLB-hit access. Permission success must precede irreversible device access or store publication. SATP/PMP writes, SFENCE/HFENCE, and privilege return establish the epoch at which subsequent accesses use the new context. A fixed controller drain count is not a proof that every variable-latency owner has drained.

SMT2 promotion follows those shared contracts. First retain the single-hart configuration as a diagnostic control; then add a named two-hart target with the intended drained or mixed-resident policy stated explicitly. For mixed residency, use per-hart commit heads, per-access CSR/MMU/FP context, same-hart younger cancellation, per-hart rename checkpoints, and restart authority based on the dispatch frontier rather than an inactive hart's retirement. `NrIssuePorts` controls issue capacity, not Linux hart count. Latency accounting is per dependency. For an overlapped load, the publication bound is `max(data-ready, forward-ready, final-order-verdict, permission-ready) + publication service`, all measured from a common accepted-request edge. For an isolated dependent chain of latency L, OoO cannot improve the dependence bound of one completion per L cycles. For independent throughput r, the in-flight capacity condition `window >= r × L` is necessary but insufficient because issue, PRF, LSQ, memory, and completion ports can each limit service. SMT hides latency only when another hart supplies independent eligible work and shared credits remain available. Those conditions replace the old blanket statement that all value-stage delays are absorbed.
