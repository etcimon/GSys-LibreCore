## 1. Correction to the record (T9, §0 of the coding philosophy)

**r39 part 1 named the owner, not the first-false promise.** It attributed the 16.26M miss to "the wbuffer retire released an entry on an earlier ACK while a re-drain of the same entry's bytes was still in flight", and the undocumented r40 change repairs exactly that: an entry is owned until its *last* in-flight return. That is a correct hardening of the release side (channel 3/4 of P3: state must not be freed while still owed). It is not the first promise that was false in the trace.

Segment card:

```text
QUESTION       Which promise was first false in the r39 window (wt_tx @16263524 id=3, wt_tx @16263525 id=2)?
ENVELOPE       r38 model, HypCfg.WbufPipelined=1 (hyp8), fw a9218107, 16.29M-cycle windowed probe.
CONTRACT       wbuffer → memory: "a byte is sent at most once per dirty epoch; a word with any byte in
               flight is not re-sent" — the module's own byte-state machine {000,110,101,111} and the
               header comment "we cannot retransmit a word that is already in-flight since the multiple
               transactions might overtake each other in the memory system" (bdirty excludes txblock).

               apart, before any merge; both returns later resolve ptr=0.

               H-ADAPT  the adapter level-acks a held request twice (the r40 leaf's `man_dup` reading).
```
